2 C 语言错题重考（Q1 ~ Q5）· 全部过关

Q1 结构体对齐手算

struct S { char a; int b; char c; double d; };
成员自身大小偏移量说明
a10起始位置
b44需 4 对齐 → 1~3 补 3 字节
c18紧跟 b 之后（8 是任意对齐的整数倍）
d816需 8 对齐 → 9~15 补 7 字节
sizeof(struct S) = 24（d 结束在 24，正好是最大成员 8 的整数倍，不需要再补尾部）。
重排更省：从小到大排 {char a; char c; int b; double d;} → 1+1+(补2)+4+8 = 16。
🔑 两条铁律：① 每个成员的偏移 = 自身对齐值的整数倍；② 结构体总大小 = 最大对齐值的整数倍。
操作型口诀：成员按自身大小对齐，整体按最大成员凑；从大到小排最省。
🎤 面试话术："对齐是为了让 CPU 一次总线周期就能取到数据 —— 未对齐时要跨字边界读两次，个别架构（ARM 部分指令、SPARC）直接抛异常。代价是内存里出现 padding，所以把大成员排前面能省空间。"

Q2 static 的初始化时刻

关键纠正：static int x = 5; 里的 5 不是"编译期执行的赋值语句"。
真相链条：编译器把常量初值编进目标文件的 .data 段 → 程序启动时（main 之前）由加载器一次性载入内存。
所以它从来不是一条运行时赋值语句，自然也就不存在"第二次执行" —— 这就是「只初始化一次」的机制来源。
🔑 面试标准答法：「启动时一次性初始化」，不是「编译期间初始化」。
📌 这是 Day4 错题 ③ 的正面回收 —— 当时答的是"编译期间初始化"（不严谨），今天自己说对了 loader / .data 机制。

Q3 const 参照物（满分）

写法const 相对 *锁的是谁
const int *p;左边锁值 —— *p = 5 ❌，p = &b ✅
int * const p2;右边锁指针 —— p2 = &b ❌，*p2 = 5 ✅
const int * const p3;两边都有全锁 —— 都 ❌
🔑 口诀：左定值，右定指针。参照物是 const 相对 * 的位置，不是相对变量名 —— 这正是 Day4 说反的根因（当时盯了变量名）。
自检法：反推一行代码 —— p = "x" 能过说明指针自由；*p = 'x' 报错说明值被锁。

Q4 栈为什么快（满分）

栈堆
分配动作移动 SP 一条指令（sub rsp, N）搜索空闲块 + 维护空闲链表 + 拆分块
并发每个线程独立栈，无需锁多线程需加锁保护分配器
极端情况无空闲块不够时进内核（brk / mmap）
缓存局部性好，命中率高地址分散，容易 cache miss
🔑 问"为什么快"，永远答操作成本，不答"栈小 / 连续"这类物理属性。
锚：栈是挪门牌号，堆是查表 + 记账 + 可能要跟内核申请。
🎤 面试话术："栈分配就是移动栈指针一条指令；堆要加锁、遍历空闲链表、可能还有系统调用进内核，所以慢几个数量级。另外栈的局部性更好，缓存命中率也更高。"

Q5 字符串反转（手撕）

void reverse_string(char *s) {
    if (s == NULL) return;                 /* ① 先判空 —— 加分项 */
    int i = 0, j = (int)strlen(s) - 1;     /* ② j 必须有符号 */
    while (i < j) {                        /* ③ 相遇即停 */
        char t = s[i]; s[i] = s[j]; s[j] = t;
        i++; j--;
    }
}
✅ 思路叙述完整：判空 → 找末尾 → 双指针首尾交换 → 相遇退出；全程原地，O(n) / O(1)。
追问「char *s = "hello" 调用会崩」→ 答对：字面量落在只读段，写入触发段错误。
对比：char s[] = "hello" 是栈上的可写副本，安全。
⚠️ 经典坑（面试官爱问）：j 必须用有符号 int 接。若写成 size_t j = strlen(s) - 1; —— 空串时 strlen = 0，0 - 1 在无符号下变成 SIZE_MAX，i < j 成立 → 直接越界崩溃。用 int 时 0 - 1 = -1，循环天然不执行 ✅。

3 中场深入讨论：字符串字面量 / 立即数 / 只读段

由 Q5 的「字面量为什么只读」追进去，把三类"看起来都是常量"的东西分清楚了：

类型存储位置能否取地址能否修改
字符串 "hello"只读数据段（Linux ELF 叫 .rodata）✅ 有地址❌ 只读
整数 1指令内嵌（立即数）❌ &1 不合法—
变量 int x = 1栈 / 全局（可写内存）✅ &x✅
· 字面量为什么进只读段：编译时就写进可执行文件、启动时加载器整段载入、地址固定、只读、生命周期 = 整个程序。
· 立即数为什么不占数据段：它直接编码进 CPU 指令（如 mov eax, 1 里的 1），根本没有独立内存地址 —— 所以 &1 编译期就报错。
· int *t = &1; 编译报错：1 是右值，不是对象，没有 storage，取不到地址。
📌 本机实测补充（Windows 侧叫法不同）：Windows PE 格式里这个段叫 .rdata，Linux ELF 才叫 .rodata。在 MinGW 上用 GDB 验证时，maintenance info sections .rdata 能看到权限位带 READONLY —— 这就是为什么 char *p = "abc" 一写就崩。面试时说 "只读数据段" 两种叫法都算对，能说出平台差异是加分。
🎤 可钩老本行：做过三年协议栈 —— 报文里的常量模板、netconf 的固定命名空间字符串，都是编译期进只读段；设备侧"配置模板只读、运行数据可写"的分区思路，跟 Flash / RAM 的划分是同一套逻辑。这不是背的，是干过的。

Q6 中断 vs 轮询 ✅ 过关

中断（Interrupt）轮询（Polling）
机制硬件打断当前程序 → 现场压栈 → 跳转执行 ISR → 弹栈恢复循环读标志位 / 状态寄存器，本质是阻塞等待
CPU 占用平时不占，事件来了才跳持续占着 CPU 空转
实时性好（事件即刻响应）取决于轮询间隔，可能漏事件
复杂度高（要考虑优先级 / 重入 / 竞态）低（逻辑线性，好调试）
选型判据：事件随机 / 突发 / 要求实时 → 中断；事件规律 / 能等 / 图简单 → 轮询。与单核多核无关。
🔴 ISR 三禁（必背）：
· 禁 malloc —— 分配器不可重入，且可能长时间持锁 → 死锁；
· 禁 printf —— 内部带锁、还可能阻塞在 I/O 上 → 耗时 + 不可重入；
· 禁一切耗时 / 带锁操作（浮点运算、等外设、sleep）。
🔑 ISR 铁律：只置标志 / 压队列，重活回主循环。
🎤 面试官会追问："中断里能给信号量吗？" → 要区分：中断安全版（FreeRTOS 的 xSemaphoreGiveFromISR）可以；普通版会把当前任务挂起、而中断里没有"当前任务" → 危险。能答出"用 FromISR 后缀的版本"就赢。

Q7 Flash vs RAM ✅ 过关

数据位置为什么
程序代码Flash只读，掉电不丢
常量 / 字面量Flash（只读段）只读，不需要可写内存
已初始化全局变量RAM（.data），初值拷自 Flash运行时要读写；初值随固件烧在 Flash 里
未初始化全局变量RAM（.bss）只需清零，不占 Flash（这是 .bss 存在的意义）
局部变量 / 栈RAM（栈区）临时，随调用生灭
堆（malloc）RAM（堆区）动态、可写
🔑 类比：Flash = 仓库（只读、掉电不丢、慢）；RAM = 工作台（可写、快、掉电丢）。
上电时启动代码（start.S / 启动文件）做两件事：① 把 .data 段从 Flash 拷到 RAM；② 把 .bss 段 清零。做完才跳 main。
🎤 面试官会追问：① ".bss 为什么不占固件大小？" → 未初始化 / 全零的变量不用把几百 KB 的 0 存进 Flash，链接脚本只需要记录"起点 + 长度"，启动时 memset 一下 —— 省固件体积。② "栈和堆都在 RAM，怎么分？" → 常从 RAM 两端往中间长（栈在高地址往下、堆在低地址往上），撞上就是栈溢出/堆溢出。

Q8 RTOS 基础 ✅ 三问全对

对比项裸机（Bare Metal）RTOS
执行模型while(1) + 中断，顺序执行调度器按优先级 / 时间片切换任务
阻塞影响一个任务卡死 → 全卡死卡的任务被换下 CPU，别的任务照跑
复杂度低，时序确定，易调试高（栈开销 / 竞态 / 优先级反转）
适用逻辑简单、任务少的设备任务多、有时序协同需求
① 信号量 vs 队列：队列传数据（UART 收字节 → 塞队列 → 主任务取，带缓冲和同步）；信号量传通知（give / take 计数器，只说"事件发生了"，不带数据）。
② 为什么有中断还要 RTOS：中断只管紧急入口（要求快进快出，不能在里面干重活）；RTOS 管众多任务的排队与协同（把中断里"压下的活"在后台按优先级调度完）。两者是分工，不是替代。
🔑 锚：中断管紧急入口，RTOS 管任务排队协同。

Q9 I2C vs SPI vs UART 📖 刚教完 · 下次验收

协议线数拓扑速度典型用途
UART2（TX / RX）点对点慢（~115.2K）调试串口、GPS
I2C2（SDA / SCL）多主多从（靠地址选）中（100K ~ 3.4M）传感器、EEPROM
SPI4（MOSI / MISO / SCK / CS）一主多从（靠 CS 选）最快（几十 M）Flash、LCD、SD 卡
🔑 选型口诀：要简单 + 距离稍远 → UART；引脚少 + 挂多设备 → I2C；要快 + 引脚不差 → SPI。
🎤 下次验收要能答出的追问：① I2C 为什么需要上拉电阻？（开漏输出，只能拉低不能拉高）② I2C 怎么知道从机"应答"？（第 9 个时钟的 ACK / NACK）③ SPI 的 CS 是干嘛的？（片选，拉低才听你说话 —— 这就是为什么多一个从机就多一根线）④ UART 的波特率是什么？（每秒符号数，双方必须约定一致）⑤ 这三种哪两个是同步、哪个是异步？（I2C/SPI 带时钟 = 同步；UART 无时钟 = 异步）

5 🎯 今日生效的「操作型记忆锚」（背这几句就够）

知识点操作型锚（照着做）自检法
结构体对齐成员偏移 = 自身对齐值的整数倍；总大小 = 最大对齐值的整数倍{char;int;char;double} → 24；换成从小到大排 → 16
