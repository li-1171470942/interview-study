面试问题表现点评与优化
自我介绍（RRM 重构）中讲了 98% 适配率，但没抛规模数字（19.6万设备/259万AP/14.7万次）——面试官不会主动问"系统多大"

为什么离职？中说"设备厂技术不够新、想到互联网"——略显负面，可优化为"想接触更高并发+国际化业务"
面向对象三大核心特性好答出继承/封装/多态 ✅
用自己话解释多态 + 举例差绕到 C++ 虚函数/虚指针，没讲清核心。标准答案：父类引用指向子类对象，同一接口不同实现（如 Animal a = new Dog(); a.speak()）
MongoDB 的优势是什么？差只答"schema 灵活、不像关系型要定字段"。被追问"没规范怎么管理数据"时卡住。应补：文档模型贴合对象、水平扩展（分片）、读写性能高、支持嵌套/数组
常用数据结构 / 栈和队列区别差答得混乱（"栈在类型中申请、比较快"）。标准：栈 LIFO 后进先出；队列 FIFO 先进先出；栈用于函数调用/撤销，队列用于任务调度/消息
单例模式解决什么问题？中答"创建对象消耗资源、懒加载复用"——方向对但不完整。核心：保证全局唯一实例（配置管理/连接池/日志器）
代码审查①：API 缺陷分析中✅ 答出异常处理缺失（文件不存在要 try-catch）
✅ 答出内存泄漏（缓存只增不减→OOM）
⚠️ 响应头（Content-Type）没答好
复合索引命中与排序差面试官连问 3 次都答不上（"这个不知道"）。核心考点：复合索引 {A,B,C}，查询 A+B 能命中，查询 B 单独不能（最左前缀原则）；排序若与索引顺序一致可避免内存排序
代码审查②：10万 ID 批量请求中✅ 答出连接数暴增、服务端限流、超时
⚠️ Promise.all 的问题没主动答出（一个失败全部失败），面试官提示后才补
Node 版本 / 学过新语法吗？差直接答"没学过"——减分项。应说"项目版本较老，但我关注并自学了新特性（如 optional chaining / Promise.allSettled）"
微服务怎么划分？好答出 4 微服务职责（control/server/compute/aioptimize）✅
RabbitMQ 用了什么设计模式？差"不知道"——标准：生产者-消费者模式（解耦），底层常配合观察者/发布订阅
反问环节好问了业务方向和技术栈 ✅ 拿到关键信息（见下节）

6 💡 三个可复用的经验（给后续面试）

  • ① 自我介绍必须主动抛规模数字——面试官不会问"系统多大"，要自己说"纳管 19.6 万设备、单月 14.7 万次调优"。这次全程没提，白白浪费了最有力的证据
  • ② 基础题要"能举例"，不能只背定义——多态那题你绕到 C++ 虚函数就说明没内化。准备方式：每个概念准备一个生活化例子 + 项目里的对应场景
  • ③ 答不上来时的正确姿势——这次多次出现"这个不知道"然后沉默。应该改成："这块我了解得不深，但我的理解是 XX，可能不准确，回去会补"——展示思考过程比直接放弃得分高
关于是否通过：基础题 6 道明显失分 + 索引题连续卡壳 + 代码审查不够深，通过概率较低。但这场面试价值很高——它精准暴露了你的真实短板（基础不牢 + 代码审查弱），比"面试通过但不知道自己弱在哪"更有价值。这是练手场，目标已达成。
