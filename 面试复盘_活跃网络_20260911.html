Q1 · Express + fs 文件接口：找代码缺陷

题目代码（还原）
const express = require('express');
const fs = require('fs');
const app = express();
let cache = {};                       // 内存缓存（懒加载）

app.get('/getFile', (req, res) => {
    let userId = req.query.userId;
    let fileName = req.query.fileName;
    if (cache[userId]) {              // 命中缓存就直接返回
        res.send(cache[userId][fileName]);
        return;
    }
    fs.readFile(fileName, 'utf-8', function (err, data) {
        cache[userId] = {};
        cache[userId][fileName] = data;
        res.send(data);
    });
});
你的回答：✅ 异常处理缺失（文件不存在要 try-catch）✅ 内存泄漏（缓存只增不减 → OOM）⚠️ 响应头 Content-Type 没答好
正确答案（7 个问题）：
① 参数未判空——userId/fileName 可能是 undefined，应先校验返回 400
② fs.readFile 没处理 err——文件不存在时 data 是 undefined 还被写进缓存并返回
③ 缓存只增不减 → 内存泄漏——每个用户+文件永久驻留，长期跑必然 OOM，应加 LRU/TTL
④ 路径穿越漏洞（最严重·加分项）——fileName 用户可控，传 ../../etc/passwd 可读任意系统文件！必须用 path.resolve + 白名单目录校验
⑤ 响应头 Content-Type 未设置——浏览器无法正确解析
⑥ 缓存命中判断不严谨——只判断 userId 层，没判断具体 fileName 是否存在
⑦ 并发重复读——缓存未命中时多个请求同时读同一文件（缓存击穿）
解析：这题是外企经典的"读代码找缺陷"，考察面广（健壮性 / 资源管理 / 安全 / 并发）。安全漏洞是最容易被忽略、也最能加分的一项。

Q2 · Object.assign 浅拷贝 + unshift

题目代码（还原）
const body = { name: 'Tom', hobby: ['篮球', '音乐'] };
const copy = Object.assign({}, body);   // 浅拷贝

body.name = 'Jerry';        // 改基本类型
copy.hobby.unshift('游戏');  // 改引用类型

console.log(body);
console.log(copy);
你的回答：（当场未能完整说清）
正确答案：
body: { name: 'Jerry', hobby: ['游戏','篮球','音乐'] }
copy: { name: 'Tom', hobby: ['游戏','篮球','音乐'] }
name 独立（基本类型按值复制）；hobby 共享（数组按引用复制，unshift 后两边都变）
解析：Object.assign({}, obj) 是浅拷贝——只复制第一层，嵌套对象/数组复制的是引用。要真正独立需深拷贝：structuredClone()（推荐）/ JSON.parse(JSON.stringify())（会丢函数/undefined/Date）/ lodash cloneDeep。补充考点：const 只限制变量重新赋值，不限制属性修改。

Q3 · Express 中间件初始化顺序 + async

题目代码（还原）
const app = express();

app.use(async (req, res, next) => {     // 异步带延时的中间件
    console.log('A start');
    await new Promise(r => setTimeout(r, 1000));
    console.log('A end');
    next();
});

app.use((req, res, next) => { console.log('B'); next(); });
app.get('/', (req, res) => { console.log('C'); res.send('ok'); });
你的回答：（当场未能完整说清）
正确答案：输出顺序 A start →（等 1 秒）→ A end → B → C
解析（3 个考点）：
① 中间件按注册顺序执行（洋葱模型），app.use 先注册先执行；写在路由之后的中间件不会执行
② async 中间件的 next() 时机——await 期间后续中间件全部阻塞，必须手动调 next()，忘了则请求挂起至超时
③ Express 4 不自动捕获 async 错误——async 函数抛错不会进错误中间件，会变成 unhandledRejection；需 try-catch + next(err) 或 express-async-errors；Express 5 才原生支持

Q4 · Promise executor 的返回值被忽略

题目代码（还原）
function foo() {
    return Promise.reject('出错了');
}
const p = new Promise((resolve, reject) => {
    foo();          // 调用一个「返回 rejected promise」的函数
});
p.catch(err => console.log('catch:', err));
console.log('end');
你的回答：（当场未能完整说清）
正确答案：只打印 end，catch 永远不执行；同时产生 UnhandledPromiseRejection 警告
解析：Promise 构造函数里 executor 的返回值被完全忽略——只看你是否调用了 resolve() / reject()。所以 foo() 返回的 rejected promise 被丢弃，外层 p 永远 pending，catch 不会触发。
正确写法：new Promise((resolve, reject) => foo().catch(reject)).catch(...)；或更直接 foo().catch(err => console.log(err))（根本不用包一层）。
延伸：executor 里 throw 等价于 reject；catch 返回新 promise，可继续链式 .then() 做错误恢复。

Q5 · 10 万 IP 用 Promise.all 批量请求

题目代码（还原）
const ips = users.map(u => u.ip);        // 10 万个
let results = [];
await Promise.all(
    ips.map(ip => axios.get(`http://api/user?ip=${ip}`))
).then(res => { results = res.map(r => r.data); });
你的回答：✅ 没捕获异常 ✅ 10 万并发可能打爆服务器 TCP 端口 ✅ 没有超时兜底机制　❌ 漏了 Promise.all 一票否决（面试官提示后才补）
正确答案（7 个问题）：
① 无异常捕获——任一失败整体崩（你答出 ✅）
② 无并发控制——10 万并发耗尽 TCP 端口（默认约 2.8 万）与文件描述符（EMFILE）（你答出 ✅）
③ Promise.all 一票否决（最核心）——10 万请求里任何一个失败，整体 reject，已成功的全部丢弃；应用 Promise.allSettled（面试官最想听的）
④ 无超时兜底——某请求卡住则整体永久 pending（你答出 ✅）
⑤ 内存暴涨——10 万个 pending promise + 全部响应体同时驻留 → OOM
⑥ 无重试机制——偶发失败直接丢数据，应指数退避重试
⑦ 对目标服务是 DDoS——可能被限流/封禁；且无连接复用（应开 keep-alive）
正确写法：p-limit 限并发（如 20）+ Promise.allSettled + timeout + 重试 + 分批 + keep-alive Agent。
口诀：看到 Promise.all 做批量操作 → 第一反应就是"一票否决"问题。

Q6 · MongoDB 复合索引 {a:1, b:1, c:-1} 的排序命中

题目：索引为 {a:1, b:1, c:-1}，下列三个查询能否用索引排序？
A. find({a:1}).sort({c:-1})　B. find({a:1,b:1}).sort({c:-1})　C. find({a:1}).sort({b:1,c:-1})
你的回答：❌ 面试官连问 3 次都答不上（本场最严重失分）
正确答案：
A ❌ 不能——只命中 a、跳过 b，c 在索引中非全局有序 → 走内存排序（SORT）
B ✅ 能——a、b 都是等值查询，前两列锁死，c 在索引中自然有序
C ✅ 能——a 等值锁定，排序 b:1,c:-1 与索引方向完全一致
解析（3 条核心规则）：
① 最左前缀原则：查询条件必须从索引最左列开始连续匹配
② 排序能否用索引：排序字段前面的所有字段必须是等值查询（缺失或有范围查询都会截断有序性）
③ 排序方向：必须与索引全同向或全反向，混用方向则无法复用索引
验证方式：explain('executionStats') 看 winningPlan——出现 SORT 就是内存排序（❌），理想是只有 IXSCAN 无 SORT（✅）。
