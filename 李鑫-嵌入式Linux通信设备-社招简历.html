① C 动态库跨语言调用架构设计与内存治理 　C 侧接口设计 / 核心开发
2024.01 – 2024.12
C 语言函数指针回调机制动态库（.so）内存管理跨语言调用性能压测
现网调优算法以 C 实现并封装为动态库（.so），由上层服务跨语言调用。原实现采用"一次性输入输出"（单次大数组传参），在万级设备批量调优时内存峰值过高、频繁 OOM，成为系统规模化的性能瓶颈。
  • 接口与数据分片设计：重新设计 C ↔ 上层调用接口，把"单次大数组传参"改造为定长缓冲区 + 分片传输 + 回调返回，内存峰值由 O(n) 降为 O(chunk)，从根因消除 OOM。
  • C → 上层反向调用（函数指针注册表）：跨语言调用层不支持异步，设计「函数名 → 函数指针」映射表与初始化注册机制，把上层回调函数注册给 C 侧、指针固化为全局函数指针表，实现 C 主动回调上层（等价于 C 侧依赖注入）。
  • 异步回调协议（method–data–callback）：设计三段式协议承载异步返回与嵌套调用（回调内再发起调用），保证多层算法组合下调用链的正确性与可重入性。
  • 跨语言内存所有权模型：明确边界两侧的内存归属与释放责任（谁分配谁释放），杜绝重复释放与悬空引用；结合压测定位内存增长点。
  • 崩溃与内存问题定位：基于 GDB 调试 C 侧崩溃（断点 / 单步 / 调用栈回溯），通过 core dump 分析定位段错误与内存越界，配合场景复现验证修复。
项目成果
  • 支撑 10 万/s 调用量的压力测试，大数据量场景 OOM 问题解决，为后续规模化调优奠定底层能力。
  • 该接口层成为算法侧与业务侧解耦的稳定边界，新增算法无需改动上层业务代码。
