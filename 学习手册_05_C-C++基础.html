指针与引用的区别？const 修饰指针的情况

概念

指针是存地址的变量（可空、可改指向），引用是变量的别名（必须初始化、不可改）；const 放 * 前修饰指向的内容，放 * 后修饰指针本身。

面试官会怎么问
  • 为什么传参优先用 const 引用？→ 避免拷贝 + 防止误改
查看答案与原理
  • 指针：int *p = &a; 可指向别处、可空；sizeof(指针)=8（64 位）
  • 引用：int &r = a; 是别名，必须初始化、不能改绑、不能空；传参用引用避免拷贝
  • const 组合：
    • const int *p / int const *p：指针指向的内容不可改（指向 const int）
    • int *const p：指针本身不可改（const 指针）
    • const int *const p：两者都不可改
  • 记忆口诀：const 修饰离它最近的类型/变量——* 前是内容，* 后是指针
拓展
先说引用=别名（底层也是指针实现），再说 const 口诀。追问：为什么传参优先用 const 引用？→ 避免拷贝 + 防止误改。

static 关键字的作用

概念

static 让对象生命周期延长 / 作用域受限：修饰局部变量（生命周期全局）、全局变量（仅本文件）、成员变量/函数（属于类不属于对象）、类内变量（所有实例共享）。

面试官会怎么问
  • static 局部变量存在哪？→ 全局区（静态存储区）
查看答案与原理
  • 静态局部变量：只初始化一次，函数退出不销毁，下次进入沿用（计数器常用）
  • 静态全局/函数：限制在本翻译单元（类似文件私有），避免多文件重名
  • 静态成员变量：所有对象共享一份，类外定义；静态成员函数：不依赖对象，不能访问非静态成员（没有 this）
  • C 里 static 是"文件级私有"，C++ 里多了"类级共享"语义
拓展
分层答"存储/作用域/类语义"。追问：static 局部变量存在哪？→ 全局区（静态存储区）。

野指针/悬空指针/内存泄漏

概念

野指针=未初始化/指向已释放内存的指针；悬空指针=指向已 delete 的内存；内存泄漏=分配了没释放（堆内存越占越多）。

面试官会怎么问
  • 你的 node-ffi 场景怎么防泄漏？→ 调 C 库分配的内存必须调对应释放函数，Buffer 生命周期管理
查看答案与原理
  • 野指针：声明未初始化（随机地址）、free 后没置 NULL、指针超出作用域——访问会段错误/脏数据
  • 悬空指针：delete p 后 p 仍指向已释放内存（用 p 前要置 NULL，C++11 后用智能指针）
  • 内存泄漏：new 了没 delete、容器里指针没清、异常路径没释放——长期运行内存涨、OOM
  • 排查：Valgrind（内存检测）、ASan（AddressSanitizer，编译期插桩）、泄漏检测工具
拓展
回答"指针三大坑" + 治本方案"RAII/智能指针"（栈对象析构自动释放）。追问：你的 node-ffi 场景怎么防泄漏？→ 调 C 库分配的内存必须调对应释放函数，Buffer 生命周期管理。

智能指针 unique_ptr / shared_ptr / weak_ptr

概念

RAII 思想——栈上智能指针对象管理堆内存，析构自动释放；unique 独占、shared 共享计数、weak 观察不计数。

面试官会怎么问
  • weak_ptr 怎么判断对象还活着？→ lock() 返回空则已释放
查看答案与原理
  • unique_ptr：独占所有权，不可拷贝可移动（move），析构自动 delete；make_unique<T>()
  • shared_ptr：引用计数，最后一个销毁时释放；make_shared<T>()；线程安全计数（对象本身不保证）
  • weak_ptr：不增加计数（解决循环引用），lock() 提升为 shared_ptr 判断对象是否存活
  • 循环引用问题：A 持 B 的 shared_ptr、B 持 A 的 shared_ptr → 计数永远不为 0 → 泄漏；解法：一边用 weak_ptr
  • 底层：shared_ptr 内部两个指针（对象 + 控制块含计数）；make_shared 一次分配效率高
拓展
必考题，讲清三兄弟职责 + 循环引用场景。追问：weak_ptr 怎么判断对象还活着？→ lock() 返回空则已释放。

深拷贝 vs 浅拷贝？何时手写拷贝构造

概念

浅拷贝只复制指针（两个对象指向同一块内存，析构两次崩溃）；深拷贝复制内容（各自独立内存）；类里有裸指针/堆资源时必须手写。

面试官会怎么问
  • 三法则是什么？→ 定义了析构/拷贝构造/赋值中任一个，通常三个都要
查看答案与原理
  • 默认拷贝构造 = 浅拷贝（逐成员复制）：含指针时两个对象共享堆内存 → 双重释放/悬空
  • 深拷贝：new 新内存 + 复制内容
  • 需要手写的场景：类持有堆资源（指针/文件句柄/锁）；遵循三/五法则（析构+拷贝构造+赋值运算符，C++11 加移动构造/移动赋值）
  • 现代做法：用 std::string/vector/智能指针代替裸指针 → 默认拷贝就是深拷贝，不用手写
拓展
"裸指针才需要手写，容器/智能指针自动深拷贝"。追问：三法则是什么？→ 定义了析构/拷贝构造/赋值中任一个，通常三个都要。

虚函数/纯虚函数/虚函数表(vtable)？多态如何实现

概念

虚函数实现运行时多态；每个含虚函数的类有一张虚函数表（vtable），对象头存 vptr 指针，调用时查表跳转——动态绑定。

面试官会怎么问
  • 析构函数为什么必须是虚的？→ 基类指针 delete 子类对象时，非虚析构只调基类析构 → 子类资源泄漏（见下题）
查看答案与原理
  • 声明：基类 virtual void func()；子类 override 重写
  • 纯虚函数：virtual void func() = 0; → 类变抽象类，不能实例化，子类必须实现
  • 原理：编译期每个类生成 vtable（函数指针数组）；对象内存开头放 vptr → 运行时根据实际对象类型查自己的 vtable 调对应实现
  • 多态条件：继承 + 虚函数重写 + 基类指针/引用调用
  • 开销：一次间接跳转 + vptr 内存；构造函数不能是虚函数（vptr 还没建好）
拓展
能讲出"vptr + vtable + 动态绑定"三步就是高级。追问：析构函数为什么必须是虚的？→ 基类指针 delete 子类对象时，非虚析构只调基类析构 → 子类资源泄漏（见下题）。

构造函数/析构函数能否是虚函数？析构为什么 virtual

概念

构造函数不能是虚函数（对象还没建好没有 vptr），析构函数应该是虚函数（基类指针删子类对象时保证子类析构被调用）。

面试官会怎么问
  • 为什么基类析构虚了子类析构才被调？→ 虚函数机制：delete 时按实际类型查 vtable 调 Derived 析构，再自动调 Base 析构
查看答案与原理
  • 构造不能虚：虚调用依赖 vptr，而 vptr 在构造函数里才初始化；构造时对象类型未定型
  • 析构必须虚：Base *p = new Derived; delete p;——若析构非虚，只会调用 Base 析构，Derived 的资源（成员对象/动态内存）不释放 → 泄漏
  • 注意：即使基类没有资源，只要被继承且可能用基类指针 delete，基类析构就该 virtual（成本：多一个 vtable 条目）
  • 纯虚析构：可以，但要给定义（子类析构最终会调用它）
拓展
"构造时类型没定、析构要照顾子类"两句话。追问：为什么基类析构虚了子类析构才被调？→ 虚函数机制：delete 时按实际类型查 vtable 调 Derived 析构，再自动调 Base 析构。

重载/重写/隐藏的区别？C++ 与 C 的区别

概念

重载=同名不同参（同作用域），重写=子类覆写虚函数（override），隐藏=子类同名函数遮蔽基类（不管参数）；C++ 相对 C 多了类/继承/多态/模板/异常/重载等。

面试官会怎么问
  • 重载和重写哪个是编译期哪个是运行期？→ 重载编译期（静态绑定），重写运行期（动态绑定，虚函数）
查看答案与原理
  • 重载 overload：同一作用域，函数名同参数不同（类型/个数/const）→ 编译期决议
  • 重写 override：子类重写基类虚函数，参数签名一致 + virtual + （最好加 override 关键字）
  • 隐藏 hiding：子类定义了和基类同名函数（不管参数是否相同）→ 遮蔽基类版本（加 using Base::f 暴露）
  • C vs C++：C 面向过程、无类/继承/多态、无重载/模板/异常/引用、malloc/free、结构体无方法；C++ 兼容 C + 面向对象 + 泛型（模板）+ STL + RAII
拓展
三个"重"字区别背熟（重载/重写/隐藏），是 C++ 入门必考。追问：重载和重写哪个是编译期哪个是运行期？→ 重载编译期（静态绑定），重写运行期（动态绑定，虚函数）。

结构体内存对齐

概念

成员按自身对齐数对齐，结构体总大小是最大对齐数的整数倍；对齐为了 CPU 一次性读全（空间换时间）。

面试官会怎么问
  • 网络传输结构体要注意什么？→ pack(1) 去掉对齐 + 注意大小端（协议设计）
查看答案与原理
  • 对齐规则：每个成员偏移 = min(自身大小, 默认对齐数=8) 的整数倍；总大小 = 最大成员对齐数的整数倍
  • 示例： cpp struct A { char c; int i; }; // c 偏移0，i 偏移4，总大小8（不是5） struct B { char c1; char c2; int i; }; // 总大小8
  • 调整：#pragma pack(1) 紧凑（省空间损性能，网络协议/文件格式用）
  • 为什么：CPU 按字（4/8 字节）访问内存，不对齐要读两次再拼
拓展
背规则 + 算一个例子。追问：网络传输结构体要注意什么？→ pack(1) 去掉对齐 + 注意大小端（协议设计）。

vector 底层与扩容？map vs unordered_map

概念

vector 是动态数组，扩容按约 2 倍（搬迁+拷贝，迭代器失效）；map 红黑树有序 O(log n)，unordered_map 哈希表无序 O(1)。

面试官会怎么问
  • unordered_map 为什么默认不用？→ 无序 + 哈希函数开销 + rehash 抖动
查看答案与原理
  • vector：连续内存，尾插 O(1)，中间插 O(n)；size 到 capacity 时扩容：新空间 2 倍 → 拷贝/移动旧元素 → 释放旧内存（迭代器/指针失效）
  • 优化：reserve() 预分配；shrink_to_fit() 收缩
  • map：红黑树，key 有序，支持范围查找；内存占用高
  • unordered_map：哈希表，平均 O(1)，无序；哈希冲突用链地址法，rehash 时全量重排（可能卡顿）
  • 选择：需要有序/范围遍历用 map，只查 key 用 unordered_map
拓展
vector 扩容讲"2 倍 + 迭代器失效"是考点。追问：unordered_map 为什么默认不用？→ 无序 + 哈希函数开销 + rehash 抖动。

红黑树 vs 哈希表，适用场景

概念

红黑树=自平衡二叉搜索树（有序、O(log n)、范围查询），哈希表=数组+哈希函数（O(1) 等值、无序）。

面试官会怎么问
  • 为什么 HashMap 当负载因子 0.75 扩容？→ 空间与冲突率平衡
查看答案与原理
  • 红黑树：节点红/黑染色保证最长路径≤2 倍最短路径（近似平衡）；插入删除 O(log n) 旋转调整；支持顺序遍历、范围、前驱后继
  • 哈希表：key → 哈希函数 → 槽位；冲突链地址/开放寻址；rehash 扩容
  • 场景：需要排序/范围（排名、区间）用红黑树；只需等值查找（id 查对象）用哈希表
  • 工程：STL map/set 红黑树；unordered_map 哈希；MongoDB/Redis 各有使用
拓展
一句"有序+范围用树，等值+快用哈希"。追问：为什么 HashMap 当负载因子 0.75 扩容？→ 空间与冲突率平衡。

sort 底层实现（快排+插排+堆排）

概念

STL sort 是混合排序：快排为主，元素少用插入排序，递归过深退化时用堆排序兜底。

面试官会怎么问
  • 为什么不用纯快排？→ 最坏 O(n²) 和递归栈溢出
查看答案与原理
  • 数据量大：快速排序（三数取中选枢轴）
  • 递归到小区间（如 ≤16）：插入排序（小数组开销小、cache 友好）
  • 快排递归深度过深（最坏 O(n²) 风险）：转堆排序（保证 O(n log n)）
  • stable_sort：归并排序（保持相等元素相对顺序）
  • 算法复杂度：平均 O(n log n)，快排最坏 O(n²) 但混合后几乎不会发生
拓展
讲"三种算法分工"（快排主 + 插排小 + 堆排兜底）就是懂源码。追问：为什么不用纯快排？→ 最坏 O(n²) 和递归栈溢出。

deque / set / multiset 底层与特性

概念

deque 双端队列（分段连续，头尾 O(1)），set 有序唯一集合（红黑树），multiset 有序可重复（红黑树）。

面试官会怎么问
  • deque 和 vector 选哪个？→ 频繁头尾操作用 deque，追求随机访问 cache 局部性用 vector
查看答案与原理
  • deque：多段连续缓冲区 + 中控器（map 指针数组），头尾插入删除 O(1)，随机访问 O(1)（比 vector 慢）；中间插 O(n)
  • set：红黑树，元素唯一且有序；insert 返回 pair（迭代器+是否成功）；底层就是 key 节点的红黑树
  • multiset：允许重复，count() 返回重复个数；erase 会删所有相等的
  • 衍生：map=key-value 红黑树；priority_queue=堆（默认大顶堆）
拓展
区分"set 去重有序 / unordered_set 去重无序"。追问：deque 和 vector 选哪个？→ 频繁头尾操作用 deque，追求随机访问 cache 局部性用 vector。

哈希冲突的解决方式

概念

链地址法（每个槽挂链表，STL 默认）和开放寻址法（线性/二次探测找空位）；负载因子高时扩容。

面试官会怎么问
  • 为什么 HashMap 桶里转红黑树的阈值是 8？→ 泊松分布下概率极低，兼顾空间
查看答案与原理
  • 链地址法：冲突的元素挂链表/红黑树（JVM 8 后链表→红黑树）；实现简单、删除方便；哈希表+链表
  • 开放寻址法：冲突后按探测序列找下一个空槽：线性探测（+1，有聚集问题）/二次探测（+i²）/双重哈希；删除要标记
  • 负载因子：元素数/桶数，过高冲突多 → 扩容 rehash（一般 0.75）
  • 退化：哈希函数设计差（如全相同的 key）→ 全挂链表 → O(n)
拓展
两个方案各说一句 + "负载因子 0.75 扩容"。追问：为什么 HashMap 桶里转红黑树的阈值是 8？→ 泊松分布下概率极低，兼顾空间。

线程与进程区别？mutex/condition_variable/atomic

概念

进程是资源分配单位（独立内存），线程是调度单位（共享进程内存）；mutex 互斥锁、condition_variable 条件变量、atomic 原子变量。

面试官会怎么问
  • condition_variable 为什么需要锁配合？→ wait 前必须持锁，内部原子地"释放锁+阻塞"，防止通知丢失
查看答案与原理
  • 进程：独立地址空间、切换开销大、通信靠 IPC；线程：共享地址空间、切换快、天然共享数据但需同步
  • mutex：lock()/unlock() 或 lock_guard（RAII 自动解锁）；保护临界区
  • condition_variable：wait 释放锁并阻塞，notify_one/all 唤醒；解决"轮询等待"问题（生产者消费者）
  • atomic：原子操作（lock-free），int 计数用 atomic 比 mutex 高效；memory_order 控制可见性
  • 死锁例子：两个线程各持一把锁等另一把
拓展
进程/线程 + 三种同步手段一句话各一个。追问：condition_variable 为什么需要锁配合？→ wait 前必须持锁，内部原子地"释放锁+阻塞"，防止通知丢失。

死锁的四个必要条件？如何避免

概念

互斥 + 持有并等待 + 不可剥夺 + 循环等待，四者同时满足才死锁；破坏任何一个即可避免。

面试官会怎么问
  • 你项目里见过死锁吗？（可讲 Kafka 消费者 + DB 锁的顺序问题，或锁顺序约定）
查看答案与原理
  1. 互斥：资源一次只能被一个线程占用
  2. 持有并等待：持有一个资源等待另一个
  3. 不可剥夺：资源不能被强行抢走
  4. 循环等待：A 等 B、B 等 A 形成环
  • 避免：按固定顺序加锁（破坏循环等待，最常用）、一次申请所有锁（破坏持有等待）、加锁超时（可剥夺）、锁粒度最小化
  • 排查：gdb 看线程栈、pstack；ps -T + 栈分析
拓展
背四条件 + "按序加锁"解法。追问：你项目里见过死锁吗？（可讲 Kafka 消费者 + DB 锁的顺序问题，或锁顺序约定）。

线程池如何实现？任务队列+工作线程

概念

线程池 = 一组常驻工作线程 + 一个任务队列 + 提交/调度逻辑；任务来了放队列，空闲线程取任务执行。

面试官会怎么问
  • 任务队列用什么数据结构？→ std::queue + mutex 保护，或用无锁队列
查看答案与原理
  • 组成：任务队列（mutex + condition_variable）、N 个工作线程（启动时创建，循环取任务）、线程安全提交接口
  • 流程：提交任务 → 加锁入队 → notify 一个线程；线程阻塞在条件变量 → 被唤醒取任务 → 执行
  • 好处：避免频繁创建/销毁线程（开销大）；控制并发数（防资源耗尽）；复用
  • 参数：核心线程数、最大线程数、队列容量、拒绝策略（类似 Java 线程池）
  • 线程数选择：CPU 密集 ≈ 核数+1；I/O 密集可更多（等待 I/O 时不占 CPU）
拓展
讲"队列+工作线程+条件变量"结构。追问：任务队列用什么数据结构？→ std::queue + mutex 保护，或用无锁队列。

socket 编程 TCP 服务端完整流程

概念

socket → bind → listen → accept（循环）→ recv/send → close；客户端 socket → connect → send/recv → close。

面试官会怎么问
  • 服务端怎么支持上万连接？→ 单线程 + epoll + 非阻塞
查看答案与原理
  • 服务端：socket(AF_INET, SOCK_STREAM, 0) → bind(端口) → listen(backlog) → accept() 返回新 fd（每次连接）→ 收发 → close()
  • 客户端：socket() → connect(ip:port)（触发三次握手）→ 收发 → close()
  • 多连接处理：fork/多线程/select/epoll 模型
  • 关键点：accept 返回的 fd 和监听 fd 分开；backlog 是未完成握手队列长度；非阻塞 + epoll 才是高并发
拓展
把流程背熟 + 画三次握手对应位置（connect 对应 SYN）。追问：服务端怎么支持上万连接？→ 单线程 + epoll + 非阻塞。

select / poll / epoll 的区别（通信厂必问）

概念

select 有 1024 fd 上限且全量遍历，poll 无上限但仍全量遍历，epoll 事件驱动只返回就绪 fd（Linux 高并发首选）。

面试官会怎么问
  • select / poll / epoll 的区别（通信厂必问）？
查看答案与原理
select poll epoll
fd 上限 1024（FD_SETSIZE） 无（链表） 无
通知方式 全量遍历 O(n) 全量遍历 O(n) 就绪回调 O(1)
复制 每次拷贝 fd 集到内核 同左 mmap 共享，免拷贝
触发 水平触发 水平触发 LT + ET
跨平台 Win/Linux Linux Linux
- epoll 结构：epoll_create → epoll_ctl（注册 fd）→ epoll_wait（等待就绪）；就绪列表直接返回
- LT（水平）：有数据就反复通知；ET（边沿）：状态变化通知一次，要一次读完（配合非阻塞）
话术/例题：通信/网络岗必考，对比表背熟 + 结论"高并发用 epoll"。追问：ET 模式为什么必须非阻塞读？→ 一次读不完要循环读，阻塞会卡住。

阻塞/非阻塞、同步/异步？I/O 多路复用

概念

阻塞=等数据才返回，非阻塞=立即返回轮询；同步=自己等结果，异步=完成通知我；I/O 多路复用=一个线程管多路 IO（见手册 03 第 2 题，同源知识）。

面试官会怎么问
  • Node.js 用的是哪种？→ 非阻塞 I/O + 事件循环（I/O 多路复用模型）
查看答案与原理
  • 四个组合（经典）：
    • 阻塞同步：read 挂起等数据
    • 非阻塞同步：read 立即返回 EAGAIN，轮询
    • I/O 多路复用：select/epoll 通知哪个 fd 就绪（阻塞在 wait，但能等很多路）
    • 异步（AIO/io_uring）：内核复制完数据再通知回调，应用不参与等待
  • 网络编程推荐：非阻塞 + epoll（事件驱动）
拓展
能区分"阻塞/非阻塞"（等的方式）和"同步/异步"（谁通知结果）两个维度就是概念清晰。追问：Node.js 用的是哪种？→ 非阻塞 I/O + 事件循环（I/O 多路复用模型）。

静态库 vs 动态库

概念

静态库（.a/.lib）编译期打包进可执行文件（大、独立、更新要重编）；动态库（.so/.dll）运行期加载（小、共享、可热更新）。

面试官会怎么问
  • 动态库依赖找不到怎么排查？→ ldd 命令查看依赖
查看答案与原理
  • 静态库：ar 打包 .o；链接时拷贝到程序 → 程序大、部署简单、不依赖环境；更新库要重新编译链接
  • 动态库：编译期只记录符号，运行期 dlopen/ld.so 加载 → 程序小、多进程共享内存、可独立更新（替换 .so）；缺点：依赖环境（缺 .so 跑不起来，"libxxx.so: cannot open shared object"）
  • 链接顺序：动态库有 PLT/GOT 延迟绑定
  • 你 node-ffi 加载的就是动态库（.so），dlopen 原理一致
拓展
对比"打包 vs 加载"一句话。追问：动态库依赖找不到怎么排查？→ ldd 命令查看依赖。

extern "C" 的作用

概念

告诉 C++ 编译器按 C 的方式链接（不做名字修饰），让 C++ 代码能调用 C 写的库函数。

面试官会怎么问
  • C 和 C++ 可以互相调用吗？→ 可以，用 extern "C" 约定接口
查看答案与原理
  • 原因：C++ 支持重载，编译时会对函数名做名字修饰（name mangling）（如 _Z3fooi）；C 不做 → 链接时找不到 C 库的符号
  • 用法：extern "C" { #include "c_lib.h" } 或在 C 头文件里 #ifdef __cplusplus extern "C" { #endif
  • 你 node-ffi 调 C 库（.so）时，头文件的函数必须 extern "C" 才能被正确链接——这就是你的实战连接点
拓展
"C++ 名字修饰 vs C 不修饰"一句本质。追问：C 和 C++ 可以互相调用吗？→ 可以，用 extern "C" 约定接口。

头文件守卫 #pragma once vs #ifndef

概念

两者都防头文件重复包含；#ifndef 是标准宏守卫（兼容所有编译器），#pragma once 是编译器指令（更快，但非标准）。

面试官会怎么问
  • 宏守卫宏名重复了会怎样？→ 第二个文件被跳过，类型未定义报错
查看答案与原理
  • #ifndef XXX_H + #define XXX_H + #endif：靠宏判断，标准做法，任何编译器支持
  • #pragma once：编译器记住该文件只包含一次，更快（不用维护宏名），主流编译器（GCC/Clang/MSVC）都支持
  • 区别：宏守卫需要宏名唯一（重名会失效）；pragma once 对"同一文件不同路径"的判断依赖编译器
  • 实践：现代代码两者任选，团队统一；推荐 #pragma once（简洁）
拓展
一句"都能防重复包含，标准 vs 便捷"。追问：宏守卫宏名重复了会怎样？→ 第二个文件被跳过，类型未定义报错。

C++11/14/17 新特性？右值引用/移动语义/move

大端小端字节序

  • 判断：union 里放 int 看 char 首字节；或取地址强转 char
  • 转换：htons/htonl（主机→网络）、ntohs/ntohl（网络→主机）
  • 场景：网络协议字段、文件格式、跨端数据交换（你 netconf 报文就涉及）
