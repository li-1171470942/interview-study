配套《面试八股复习计划》第 4、5 节 模板：一句话结论 → 详细解释 → 手写模板/话术 算法：大厂笔试/手写必考；项目：所有面试 60% 时间都在这里——决胜盘

第一部分：高频算法（手写模板）

算法建议：每天 20 分钟，手写以下 8 个模板到肌肉记忆。LeetCode 按"链表→树→数组→动态规划"顺序刷。

1. 两数之和

一句话结论：哈希表存"值→下标"，遍历一遍 O(n)。 模板：

int[] twoSum(int[] nums, int target) {
    Map<Integer,Integer> map = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (map.containsKey(need)) return new int[]{map.get(need), i};
        map.put(nums[i], i);
    }
    return new int[]{};
}

追问：要求不重复用自己/排序数组变体（双指针）。

2. 反转链表

一句话结论：三指针（prev/cur/next）遍历翻转。 模板：

ListNode reverseList(ListNode head) {
    ListNode prev = null, cur = head;
    while (cur != null) {
        ListNode next = cur.next;
        cur.next = prev;
        prev = cur; cur = next;
    }
    return prev;
}

追问：K 个一组翻转（先写"翻转一段"子函数）。

3. 手写快速排序

一句话结论：选基准 → 分区 → 递归；平均 O(n log n)。 模板：

void quickSort(int[] a, int l, int r) {
    if (l >= r) return;
    int i = l, j = r, pivot = a[l];
    while (i < j) {
        while (i < j && a[j] >= pivot) j--;
        while (i < j && a[i] <= pivot) i++;
        if (i < j) { int t = a[i]; a[i] = a[j]; a[j] = t; }
    }
    a[l] = a[i]; a[i] = pivot;
    quickSort(a, l, i-1); quickSort(a, i+1, r);
}

追问：复杂度、最坏情况（已有序）、怎么优化（三数取中/随机）。

4. 二叉树遍历（前/中/后 + 层序）

一句话结论：递归三行；层序用队列。 模板（前序递归）：

void preorder(TreeNode r) {
    if (r == null) return;
    visit(r);
    preorder(r.left); preorder(r.right);
}

层序：Queue + while 循环 + 每层 size 记录。 追问：迭代版（栈模拟）；"树的深度"= 递归 max(left,right)+1。

5. LRU 缓存

一句话结论：哈希表 + 双向链表，get/put 都 O(1)。 思路：Map + 链表头插尾删；命中移到头部；满时删尾部。 追问：为什么必须双向链表？→ 删除节点要 O(1) 拿到前驱。

6. 二分查找

一句话结论：有序数组，每次砍半 O(log n)；注意边界（left<=right 或 left<right）。 模板：

int binarySearch(int[] a, int target) {
    int l = 0, r = a.length - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;  // 防溢出
        if (a[mid] == target) return mid;
        else if (a[mid] < target) l = mid + 1;
        else r = mid - 1;
    }
    return -1;
}

追问：旋转数组找目标 / 找第一个等于 target 的位置。

7. 合并两个有序链表

一句话结论：双指针归并，虚拟头节点简化。 追问：合并 K 个有序链表（优先队列）。

8. 动态规划入门：爬楼梯

一句话结论：dp[i] = dp[i-1] + dp[i-2]，从底向上。

int climb(int n) {
    if (n <= 2) return n;
    int a = 1, b = 2;
    for (int i = 3; i <= n; i++) { int c = a + b; a = b; b = c; }
    return b;
}

追问：最大子数组和（dp[i]=max(a[i], dp[i-1]+a[i])）。

第二部分：项目深挖（决胜盘）

原则：每个项目准备 3 层——① 30 秒概述（做了什么+结果）② 技术细节（架构/难点）③ 一个可深挖的追问（数据/原理）。 每句话都要带"为什么 + 数据"。

项目 ① AI RRM 系统重构与规模化落地（主打，2024.08-至今）

30 秒概述：原 RRM"云端收集-云端计算-下发"运维压力大、只开白名单。我主导重构为"AC+fitap 设备侧计算、云 AP 云端计算"的双计算架构，实现"下发-计算-上报-展示"闭环，二期做配置中心和规模化落地，适配现网 98%+ 组网、RRM 计算压力分流到设备侧。

技术细节准备： - 为什么双计算？→ 云端集中算力压力大（全量 AP 上报计算），设备侧算力闲置；按组网类型分流 - 下发链路？→ WebSocket + netconf 下发调优参数，Kafka 上报结果，Redis 分布式锁防并发触发 - 数据一致性？→ MongoDB 分库分表（按任务维度分片，索引 {taskId,apSN,RI}），Kafka 消息不丢（消费后提交 offset） - 配置中心？→ 配置统一管理 → 生成 ConfigMap → 一键部署 → 自动校验 → 异常回滚 - 98% 怎么算的？→ 现网 AC+fitap 组网占比统计

高频追问应对： - "线上出过什么问题？" → 准备 1 个故障复盘：现象 → 根因（如 Kafka 消费积压/内存 OOM）→ 定位（日志 grep/指标）→ 修复（内存调 5Gi→5.5Gi、批次限流）→ 预防（监控告警） - "怎么保证调优下发不失败？" → 超时重试 + 幂等（taskId 去重）+ 失败告警

项目 ② RRM 支持 WiFi7（2024.01-2024.12）

30 秒概述：RRM 原只支持 2.4G/5G，我主导新增 6GHz 频段全链路改造（采集/扫描/计算/调优/部署），用 node-ffi 调 C 算法库，从 2 频段扩展到 3 频段，支持 WiFi7 商用。

技术细节准备： - 4 个微服务链路？→ rrmcontrol 调度 / rrmserver 查询 / rrmcompute 计算 / aioptimize AI 优化 - node-ffi 细节？→ 动态库加载、Buffer 传参、内存释放、C 函数签名映射 - 6GHz 新增影响面？→ 频段参数、信道扫描范围、功率上限、页面展示全链路适配

项目 ③ WBC IoT 2.0 解耦（2023.07-2024.06）

30 秒概述：WBC 云简与物联网模块高度耦合（出版本困难、内存紧张），我主导用虚拟化方案解耦，支持"一体机+虚拟机"双镜像，实现进程级隔离、独立版本生命周期。

技术细节准备： - 为什么用虚拟机？→ 进程级解耦不彻底，虚拟机隔离更彻底且不互相影响 - VNC 通道？→ 安全通道建立、资源分配（内存紧张怎么分）

第三部分：行为面试与话术

自我介绍（1 分钟版）

重邮硕士 → 新华三 3 年 Node.js 后端 → 主导 AI RRM 重构（双计算+微服务+K8s）→ 期望 30-35 万，可接受 Go/Java。

模板："面试官好，我叫李鑫，重邮电子信息硕士，在新华三云简网络做了 3 年 Node.js 后端。主要负责 RRM 无线资源管理，主导过 AI RRM 系统重构——把它从云端集中计算改成设备侧+云端双计算架构，适配了现网 98% 的组网，同时我负责 4 个微服务的 K8s 部署和 Kafka/Redis/MongoDB 的日常运维。我的优势是：有完整的微服务架构设计经验、对分布式中间件有实战、网络通信背景扎实。期待能加入贵司贡献价值。"

离职原因（安全版）

不吐槽前东家；讲成长诉求。

模板："在新华三三年成长很快，独立扛过多个重构项目。但现在是验证/测试为主的工作内容，我希望回到纯开发主线，在更大平台、更高并发场景下继续打磨架构能力。"

  • 锚点：现年包 24.5 万 → 期望 30-35 万（涨幅 22-43%）
