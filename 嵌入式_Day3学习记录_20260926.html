2 ⭐ 错题纸更新（累计 21 条）

🔴 复发（同一坑第 2 次 · 最高优先级）

条目说明与根治锚
指针的大小（9/21 错 → 9/26 又错）sizeof(p) = 8（64 位）/ 4（32 位），与指向的类型无关（char* / int* / double* 都是 8）。
锚：sizeof 看「类型」，strlen 看「内容」；要"指向内容"的大小必须写 sizeof(*p)。
根因：把"指针"和"它指的东西"当成一体了 —— 指针只是一个装地址的格子。

🆕 今日新增

条目要点
malloc 不清零出来是垃圾值；要干净用 calloc（自动清零）或 memset。锚：malloc 只给地，calloc 给地还打扫干净
不能 free 偏移过的指针free(p + 1) ❌（块头找不到了）；必须 free malloc 返回的原指针
free(NULL) 是安全的所以"free 后置 NULL"同时防住悬空指针 + double free
SQ(1+2) = 5（不是 9）宏是文本替换 → 1 + 2 * 1 + 2；正确写法 ((x) * (x))；括号的意义是"防止替换后被拆开"不是"提优先级"
多语句宏要包起来do { ... } while(0) —— 否则塞进 if / else 会被拆成两半
结构体总大小"凑"谁凑的是 最大成员的整数倍（struct{char;int;char} → 10 → 凑到 12），不是看最后一个成员
未对齐的代价说法是"跨一个字的边界（4 / 8 字节）要读两次"，不是 4KB；个别架构（ARM 部分指令 / SPARC）直接抛异常

3 🎯 今日生效的「操作型记忆锚」（背这几句就够）

知识点操作型锚（照着做）自检法
大端 / 小端布局大端 = 顺着写；小端 = 倒着写（12 34 56 78 vs 78 56 34 12）x = 1 → 小端 01 00 00 00、大端 00 00 00 01
野 / 悬空 / 泄漏野 = 没领钥匙乱开门；悬空 = 房退了钥匙还在手上；泄漏 = 钥匙丢了房子还占着问"内存还在不在 / 指针有没有被赋过值"
结构体对齐成员按自身大小对齐，整体按最大成员凑；成员从大到小排最省struct{char;int;char} → 12；换 int;char;char → 8
sizeof / strlensizeof 看类型（编译期、含 \0）；strlen 看内容（运行期、数到 \0）char s[]="abc" → 4/3；char *p="abc" → 8/3
🎤 两条能直接说的面试话术
· 大小端："大端是高位字节放低地址（网络字节序就是大端），小端是低位字节放低地址。判断必须按字节读内存 —— union 法或 *(char*)&x == 1；位运算做不到，因为它在数值层面，跟内存布局无关。"
· volatile："volatile 强制每次从内存读写，解决可见性；三个场景是硬件寄存器、中断与主循环共享的标志位、多线程共享变量；它不保证原子性也不保证顺序性，多线程还要配 atomic。"
⭐ 可钩项目的两个点：① 他压测时真用过 volatile 全局计数器（1024 并发链 × 100 嵌套 → 10 万/s）② 处理过 rrmcompute OOM（内存配额 5Gi → 5.5Gi）—— 对"内存泄漏在长驻服务/设备上的危害"有真实体感。
