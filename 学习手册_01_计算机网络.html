TCP 和 UDP 的区别

概念

TCP 面向连接、可靠、字节流；UDP 无连接、不可靠、数据报，TCP 慢但稳，UDP 快但丢。

面试官会怎么问
  • TCP 和 UDP 的区别？
查看答案与原理
维度 TCP UDP
连接 面向连接（三次握手） 无连接
可靠性 可靠：确认重传、排序、流量控制、拥塞控制 不可靠：发出去就不管，不保证到达/顺序
传输单位 字节流（无边界） 数据报（有边界）
速度 慢（握手+重传+拥塞控制开销） 快
场景 文件传输 HTTP/FTP、网页 视频通话、直播、DNS、游戏

面试话术：先说结论"TCP 可靠连接、UDP 尽力而为"，再补一句适用场景对比（HTTP 用 TCP 因为要准确，直播用 UDP 因为能容忍丢包但不能容忍延迟），面试官会觉得你有工程视角。

例题/追问：① 视频会议为什么用 UDP 不用 TCP？→ 丢一帧还能看，卡顿半秒没法忍，TCP 重传会导致延迟堆积。② 有没有用 TCP 的实时场景？→ WebRTC 的拥塞控制/QUIC 用类 TCP 方案，UDP 之上自建可靠性。

TCP 三次握手

概念

三次握手是客户端与服务端互相确认"双方收发能力都正常"的最小通信次数。

面试官会怎么问
  • TCP 三次握手？
查看答案与原理
  1. 客户端 → 服务端：SYN=1, seq=x（"我想连你"）
  2. 服务端 → 客户端：SYN=1, ACK=1, seq=y, ack=x+1（"我收到你的，我也能发"）
  3. 客户端 → 服务端：ACK=1, ack=y+1（"我收到你的了，开始传数据"）

为什么是三次不是两次：

  • 两次握手：客户端发出的 SYN 若在网络中滞留，超时重传后服务端会收到两个 SYN 建立两条连接，旧连接残留 → 浪费资源
  • 三次握手让双方都确认对方能收能发，并同步初始序列号（防伪造/防旧连接）

面试话术：背熟三次报文（SYN → SYN+ACK → ACK），重点落在"为什么两次不行"——防止滞留的旧连接请求导致服务端建立无效连接；以及"为什么要 seq 序列号"——保证有序和防篡改。

例题/追问：① 第二次握手的 seq 和 ack 分别是什么含义？② 半连接队列（SYN Queue）是什么？→ 服务端收到 SYN 未完成三次握手的队列，攻击可占满它 → SYN Flood 攻击的原理。

3

TCP 四次挥手

概念

四次挥手是因为 TCP 全双工，双方各自独立关闭一条方向，需要 4 个报文；主动关闭方要等 2MSL 才真正断开。

面试官会怎么问
  • TCP 四次挥手？
查看答案与原理
  1. 客户端 → 服务端：FIN=1（"我数据发完了，要关了"）
  2. 服务端 → 客户端：ACK=1（"收到，但我可能还有数据要发"）
  3. 服务端 → 客户端：FIN=1（服务端数据也发完了）
  4. 客户端 → 服务端：ACK=1（确认关闭）

为什么四次：服务端的 ACK 和 FIN 不能合并——它收到 FIN 后还要继续发剩余数据，发完才发 FIN，所以中间隔了一次。

TIME_WAIT（主动关闭方等 2MSL，约 60s）的原因：

  1. 保证最后一个 ACK 能到达（丢了可以重发）
  2. 让旧连接的数据包在网络中彻底消失，防止污染新连接

面试话术：强调"全双工 → 两个方向的关闭各自独立 → 四次"，再说 TIME_WAIT 两个原因。能引出"服务端大量 TIME_WAIT 怎么排查"（netstat 统计、调 keepalive、复用端口）这种实战问题。

例题/追问：① 为什么 TIME_WAIT 是 2MSL 不是 1MSL？→ 保证最坏情况下（ACK 丢失+重传）报文也能往返。② 大量 CLOSE_WAIT 是什么问题？→ 对方关闭后己方没调 close()，通常是代码没关 socket 导致连接泄漏。

HTTP 请求方式

概念

GET 取数据、POST 提交数据、PUT 整体更新、PATCH 局部更新、DELETE 删除、HEAD 只要响应头、OPTIONS 探询跨域。

面试官会怎么问
  • HTTP 请求方式？
查看答案与原理
  • GET：幂等、参数在 URL、有长度限制、可缓存
  • POST：非幂等、参数在 body、无长度限制
  • PUT：幂等（整体替换）；PATCH：非幂等（部分修改）
  • DELETE：幂等
  • HEAD：同 GET 但只返回响应头（常用于探测资源是否存在）
  • OPTIONS：CORS 预检请求会用它

面试话术：RESTful 语义 + 幂等性两个概念一起讲（幂等=重复执行结果一致），顺便说 GET 和 POST 的区别常被追问（GET 不能带 body？规范上可以但别用；缓存差异才是本质）。

例题/追问：① 为什么 GET 比 POST 容易被缓存？② OPTIONS 预检在什么时候触发？（非简单请求：自定义 header、JSON body 等）

5

HTTP 状态码

概念

1xx 信息、2xx 成功、3xx 重定向、4xx 客户端错误、5xx 服务端错误。

面试官会怎么问
  • HTTP 状态码？
查看答案与原理

详细解释（面试高频）：

  • 200 成功、204 无内容（删除常用）、206 部分内容（断点续传/分片）
  • 301 永久重定向（换域名）、302 临时重定向、304 Not Modified（协商缓存，命中缓存）
  • 400 参数错误、401 未认证、403 无权限、404 不存在、405 方法不允许、429 限流
  • 500 服务器内部错误、502 网关错误（上游无响应）、503 服务不可用（过载/维护）、504 网关超时

面试话术：背 200/301/304/400/401/403/404/500/502/503 就够用。重点能区分 401（没登录）vs 403（登录了没权限）、502（上游挂了）vs 504（上游响应慢）。

例题/追问：① 前端缓存命中一般返回哪个码？304。② 502 和 504 的区别？（网关角度：502 连不上上游，504 上游没在时间内返回）

HTTPS 和 HTTP 的区别

概念

HTTPS = HTTP + TLS，用非对称加密协商密钥、对称加密传输数据，防窃听、防篡改、防冒充。

面试官会怎么问
  • HTTPS 和 HTTP 的区别？
查看答案与原理
  1. 加密：HTTP 明文，HTTPS 加密
  2. 握手：HTTPS 多一次 TLS 握手（约 2 RTT），主要动作： - 服务端发证书（含公钥）→ 客户端验证书（CA 签名链）→ 防中间人冒充 - 双方用非对称加密（RSA/ECDHE）协商出对称密钥 - 之后数据用对称加密（AES）传输（快）
  3. 端口：80 vs 443
  4. 证书需 CA 签发，有有效期

面试话术：一句话"混合加密——非对称协商密钥，对称加密数据"，展开三步：证书验身份 → 协商密钥 → 加密传输。能讲清"为什么不用纯非对称？慢"就是高分答案。

例题/追问：① 中间人攻击怎么防？证书校验。② TLS1.3 比 1.2 快在哪？→ 握手从 2 RTT 降到 1 RTT。

7

Cookie 和 Session

概念

Session 存在服务器（记录登录态），Cookie 存在浏览器（携带身份标识），SessionId 通过 Cookie 传递。

面试官会怎么问
  • Cookie 和 Session？
查看答案与原理
  • 流程：登录成功 → 服务端创建 Session（内存/Redis）→ 把 sessionId 放进 Set-Cookie → 浏览器存 Cookie → 后续请求自动带 Cookie → 服务端查 Session 确认身份
  • Cookie 特点：有大小限制（约 4KB）、可设置过期时间、HttpOnly 防 JS 读取（防 XSS 偷）、SameSite 防 CSRF
  • Session 特点：服务端存储，可存任意大小，分布式下要放 Redis（共享）
  • 现代替代：JWT——把用户信息签名后放客户端，服务端无状态，适合分布式/多端

面试话术：讲清"Cookie 是载体，Session 是状态"这个本质，再补一句"分布式场景 Session 要放 Redis 或用 JWT 做无状态认证"，体现工程经验。

例题/追问：① JWT 和 Session 怎么选？② 为什么 JWT 无法主动注销？（token 在客户端，只能等过期或加黑名单）

OSI 七层模型 和 TCP/IP 五层模型

概念

OSI 七层（应用/表示/会话/传输/网络/数据链路/物理）是教科书标准，TCP/IP 五层（应用/传输/网络/数据链路/物理）是实际实现。

面试官会怎么问
  • OSI 七层模型 和 TCP/IP 五层模型？
查看答案与原理

详细解释（五层对应典型协议）：

层 典型协议/设备
应用层 HTTP/HTTPS、DNS、FTP、WebSocket
传输层 TCP、UDP（端口、可靠传输）
网络层 IP、ICMP、路由（IP 地址寻址）
数据链路层 以太网、ARP、MAC 地址、交换机
物理层 网线、光纤、集线器
  • 每层职责：上层用下层服务，下层对上屏蔽细节——封装/解封装（数据包逐层加头/去头）
  • 面试常见：DNS 用的什么？UDP 53（传输层）+ 端口；ARP 在哪层？数据链路层

面试话术：背熟五层+各层协议，能画出"HTTP → TCP → IP → 以太网"的封装过程。追问时能说"为什么 OSI 把表示层/会话层合并进应用层——实际实现里不需要分开"。

例题/追问：① 一次 HTTP 请求经过哪些层？（应用→传输→网络→链路→物理，逐层加头，接收方逐层去头）。② 交换机/路由器分别在几层？（2 层/3 层）

各层常用协议

概念

应用层 HTTP/DNS/WebSocket，传输层 TCP/UDP，网络层 IP/ICMP，链路层 ARP/以太网。

面试官会怎么问
  • 各层常用协议？
查看答案与原理
  • HTTP：应用层，超文本传输
  • DNS：域名 → IP，UDP:53，层级查询（根 → 顶级 → 权威）
  • WebSocket：应用层，基于 TCP 的长连接全双工，HTTP 握手升级（101 Switching Protocols）
  • TCP/UDP：传输层
  • IP：网络层，寻址路由
  • ICMP：网络层，ping 用它（探测连通性）
  • ARP：链路层，IP → MAC

面试话术：结合你的业务讲——RRM 设备上报走 Kafka（应用层）、云端下发走 WebSocket（应用层）基于 TCP；讲协议时要能落到"我实际用过"。

例题/追问：DNS 用 TCP 还是 UDP？→ 正常 UDP:53（快），响应超大数据（DNSSEC）时切 TCP。

为什么 TCP 要建立三次握手（深入）

概念

三次握手同步了序列号、确认了双向收发能力，并防止历史重复连接（滞留 SYN）误建立连接。

面试官会怎么问
  • 为什么 TCP 要建立三次握手（深入）？
查看答案与原理

详细解释（升级版）：

  • 同步序列号：双方 seq 不同，后续按序号排序去重
  • 防滞留连接：客户端旧 SYN 比新 SYN 晚到，服务端回 SYN+ACK 后，客户端发现序号过期 → 发 RST 断开，新连接不受影响——这是"两次握手做不到的"
  • 确认双向：第一次只证明客户端能发，第二次证明服务端能收能发，第三次证明客户端能收

面试话术：层次感递进："表面是确认能力，核心是同步序列号+防滞留连接"——这样答基本满分。

例题/追问：SYN Flood 攻击怎么防？→ SYN Cookie（不分配资源，用 cookie 校验）+ 限制半连接队列长度。

对 HTTP 的理解（含 HTTP 版本演进）

概念

HTTP 是应用层无状态请求-响应协议；HTTP/1.1 引入持久连接与管线化，HTTP/2 多路复用，HTTP/3 基于 QUIC(UDP)。

面试官会怎么问
  • 对 HTTP 的理解（含 HTTP 版本演进）？
查看答案与原理
  • 无状态：服务端不记客户端状态 → 靠 Cookie/Session 补充
  • HTTP/1.0：短连接，一次请求一个连接
  • HTTP/1.1：keep-alive 持久连接；管线化（仍队头阻塞）；Host 头支持虚拟主机
  • HTTP/2：二进制分帧 + 多路复用（一个连接并发多个流，解决队头阻塞）；头部压缩 HPACK；服务端推送
  • HTTP/3：基于 UDP 的 QUIC，解决 TCP 队头阻塞（丢一个包不影响其他流），0-RTT 连接

面试话术：背版本演进表 + 每个版本解决什么问题（1.1 解决重复建连，2 解决队头阻塞，3 解决 TCP 层队头阻塞）。能说"2 的队头阻塞只是应用层没了，TCP 层丢包仍阻塞，所以 3 换 QUIC"是加分。

例题/追问：HTTP/2 还有队头阻塞吗？→ 应用层没有，但 TCP 层丢包仍会阻塞整个连接，所以才有 HTTP/3/QUIC。
