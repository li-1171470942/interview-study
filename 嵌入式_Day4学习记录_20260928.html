2 ✍️ 手撕代码 · 6 道全部答完

❌ 他直接说"我还真不会这个" → 已完整讲解，明天重考（不看答案手写）。这不是"复习"，是从零建立手撕能力。

思路（面试第一句就要说）

"两个指针，一个指头、一个指尾，交换内容后向中间夹逼，直到 i 不小于 j。全程原地，不申请新空间。"

参考实现

void reverse_str(char *s) {
    if (s == NULL) return;          /* ① 先判空 —— 加分项 */
    int i = 0, j = (int)strlen(s) - 1;
    while (i < j) {                 /* ② 相遇即停 */
        char t = s[i];              /* ③ 三步交换 */
        s[i] = s[j];
        s[j] = t;
        i++; j--;
    }
}
⚠️ 经典坑（面试官爱问）：j 必须用 有符号 int 接。若写成 size_t j = strlen(s) - 1; —— 空串时 strlen=0，0-1 在无符号下变成 SIZE_MAX，i < j 成立 → 直接越界崩溃。用 int 时 0-1=-1，循环天然不执行 ✅。
✅ 四维判分标准（明天照这个自查）：① 能否编译 ② 边界（空指针 / 空串 / 单字符）③ 是否真原地（偷偷开数组即扣分）④ 面试加分（先判空 + 主动说边界）。
锚：两手从两端往中间走，见面就散。

🔴 今日新增 · 闭卷自测（4 条）

条目要点与根治锚
把 \0 和「退化」焊死\0 管"数到哪停"（strlen 的终止符）；退化管"你是谁"（数组名在函数参数/表达式里变指针）。两条独立规则，不在一个维度。没有 \0 的后果是 strlen 越界往下读（未定义行为），不是退化。
锚：\0 管停，退化管形。
const 判断参照物错判断"左锁值 / 右锁指针"时，看的是 * 不是变量名。const char *p 和 char * const p 里 const 都在变量名左侧，但相对 * 一左一右。
锚：盯 *，谁离它近谁先被锁；两个 const = 全锁。
static 初始化时刻不是"编译期执行"，而是：编译器把常量初值编进目标文件的 .data 段，程序启动时（main 之前）由加载器一次性载入内存。它从不是一条运行时赋值语句，所以不存在"第二次执行"。
面试标准答法："启动时一次性初始化"。
"栈为什么快"答成物理属性问"为什么快"永远问的是操作成本，不是"栈小/连续"。栈 = sub rsp 一条指令（挪指针）；堆 = 加锁 + 遍历空闲链表 + 可能分裂 + 可能 brk/mmap 进内核。
锚：栈是挪门牌号，堆是查表+记账+可能要跟内核申请。

✍️ 手撕段新增（26 ~ 30 条 · 9/28 下午）

条目要点与根治锚
26 } Node; 漏 typedefstruct Node {…} Node; 里的 Node 是变量名不是类型名（实测 Node.val = 42 编译通过 = 铁证）→ 写 Node *p; 报 unknown type name。
锚：typedef = 起名字；不加 = 招个人。
⚠️ 这是 C/C++ 差异高频题：C++ 里 struct Node{}; 之后能直接写 Node，C 不行。
自检：写完结构体问一句「我是要定义类型名，还是要声明变量？」想不通就写 typedef。
27 位运算参数必须 unsignedint 为负时 n >>= 1 是算术右移、高位永远补 1 → while(n) 死循环。把 -1 传给 unsigned int 参数结果 = 32（补码位模式原样搬，一个 1 都不少）。
28 位运算题考「循环次数」while(n) n >>= 1 次数 = 最高位 1 的位置（0x80000000 → 32 次，最坏情况与方法 A 一样）；n &= (n-1) 次数 = 1 的个数（同例 → 1 次）。
锚：>> 是往下砍（砍到空，与几个 1 无关）；n&(n-1) 是掐掉一个 1（转几圈 = 有几个 1）。
📌 必背后手：n & (n-1) 还能判 2 的幂（n > 0 && (n & (n-1)) == 0）。
📌 加分：Intel POPCNT 指令 / GCC __builtin_popcount()。
29 swap32 定式掩码取出 → 移位到对面 → 按位或合并：((x&0x000000FF)<<24) | ((x&0x0000FF00)<<8) | ((x&0x00FF0000)>>8) | ((x&0xFF000000)>>24)。
0x12345678 → 0x78563412；换字节是自逆操作，转两次还原。
📌 钩老本行：这就是 htonl()，Node.js 的 buf.writeUInt32BE() 内部就干这个；面试可讲成「我做过三年协议栈，字节序转换是日常」。
30 三个严谨性小扣① 取字节一律用 unsigned char（x86 上 char 有符号）② char c[4] 应写 char c[sizeof(int)] ③ sizeof(类型) 必须带括号 —— sizeof ring_buf_t 是编译错误，sizeof 变量 才可以省。
④ 判大小端返回值用 *(unsigned char *)&x == 1 更干净（返回真布尔，不是字节值）。

🔧 环形缓冲段新增（31 ~ 33 条 · 9/28 晚）

条目要点与根治锚
31 ⭐ 形参是「指针的副本」函数里写 rb = malloc(...) 只改了副本，调用方那个对象一个字节都没动（实测仍 0xAAAAAAAA），而 malloc 出来的块再没人指向 = 内存泄漏。
正解：rb->head = rb->tail = 0;（或 memset(rb, 0, sizeof *rb)）。
锚：传指针进来是「借你地址」，不是「让你换地址」—— 参数是复印件，改复印件不改原件。
⚠️ 对比记忆：create_node 里 malloc 是对的 —— 因为它靠 return 把新地址传出去。函数要造对象 → 用返回值传出去，不要用参数带回来。
32 volatile 为什么必须加编译器会把「循环里没被改写的变量」的判断提到循环外只读一次 → 循环体只剩 jmp，永远等不到新数据。
实测铁证（-O2 汇编）：无 volatile 的 while (g == 0) n++; 循环体内 0 条 load 指令（只留 .L3: jmp .L3）；加 volatile 后每圈都有 movl g_vol(%rip), %edx 重新读内存。
head/tail 会被中断服务程序 / 另一个线程改写，编译器看不见 → 必须 volatile。
📌 关键补充：volatile 只保证「每次都去内存读」，不保证原子性！单生产 + 单消费（SPSC）可以不加锁；多生产或多消费必须靠临界区/原子操作。
33 环形缓冲「牺牲一格」head == tail 有两种身份：空（刚 init，实测 0 == 0）和满（朴素写法下 head 绕回追上 tail）→ 冲突。
三种解法：① 牺牲一格（你选的：判满 (head+1) % N == tail，代价 = BUF_SIZE=8 只能存 7 个，实测写第 8 个返回 -1）② 加 count 计数器（不浪费容量）③ 加 full 标志位。
为什么 BUF_SIZE 取 2 的幂：& (N-1) 可以完全替代 % N —— % 编译成除法指令（几十周期），& 一个周期。
📌 内核里这东西叫 kfifo（串口/tty 层在用）；用户态还有 io_uring 的 SQ/CQ ring、Kafka 生产者缓冲、Node net.Socket 内部读写缓冲。

知识点操作型锚（照着做）自检法
const 锁谁盯 *：左锁值（*p 不能改）、右锁指针（p 不能改）、左右各一个 → 全锁反推一行：p="x" 能过说明指针自由；*p='x' 报错说明值被锁
\0 vs 退化\0 管停（strlen 的刹车），退化管形（数组变指针）问"这是终止符问题，还是类型问题？"
栈 / 堆快慢栈 = 挪指针（一条指令）；堆 = 查链表 + 记账 + 可能进内核别答"大小/连续性"，那是属性不是成本
结构体对齐成员按自身大小对齐，整体按最大成员凑；从大到小排最省char;double;char → 24；double;char;char → 16
函数指针判断(*名) = 指针；名( = 函数int (*f)(int) 是变量；int *g(int) 是函数
形参改不改得到外部改 rb->x（顺着地址写内容）→ 改得到；改 rb 本身（换地址）→ 改不到问「我要改的是门牌号还是屋里的东西？」要造新对象就用 return 带出去
volatile 判断这个变量会被「编译器看不见的人」改吗？（中断、别的线程、硬件寄存器）→ 会就得加看场景：等标志位 / 等中断 / 映射寄存器 / SPSC 共享游标
环形缓存的空与满牺牲一格：判空 head == tail，判满 (head+1) % N == tail（代价：容量 N-1）自己算一遍：N=8 最多存 7 个
