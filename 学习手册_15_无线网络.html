📘 学习手册 15 · 无线网络（WLAN 深度）

你的王牌章节——RRM 无线资源管理工程师面试通信厂（中兴/锐捷/鼎桥/华为/长虹）的杀手锏 别人只会 TCP/IP，你能讲 802.11、漫游、信道调优——这就是差异化 模板：一句话结论 → 详细解释 → 面试话术/例题 结合你的 RRM 实战：调优算法、WiFi7 项目、云 AP 组网都是现成弹药

1. 802.11 协议演进（WiFi1-7）

一句话结论：802.11 协议从 a/b/g/n/ac/ax 到 be（WiFi7），速率从 11Mbps 到 46Gbps，核心技术从 OFDM → MIMO → OFDMA → MLO。 详细解释：

标准 别名 频段 核心技术 理论速率
802.11b WiFi1 2.4G DSSS 11M
802.11a/g WiFi2/3 5G/2.4G OFDM 54M
802.11n WiFi4 2.4/5G MIMO + 40MHz 600M
802.11ac WiFi5 5G MU-MIMO(下) + 80/160MHz 6.9G
802.11ax WiFi6 2.4/5G OFDMA + MU-MIMO(上下) 9.6G
802.11be WiFi7 2.4/5/6G MLO + 320MHz + 4096-QAM 46G
- 你项目：RRM 支持 WiFi7 就是 802.11be 的 6GHz 适配
话术/例题：背"每代一个核心技术"（MIMO→OFDMA→MLO）。追问：WiFi6 比 WiFi5 强在哪？→ OFDMA 多用户并行（不是轮流）+ 上下行 MU-MIMO + TWT 省电。

2. 无线频段：2.4G / 5G / 6G

一句话结论：2.4G 覆盖好但干扰大（3 个不重叠信道），5G 干扰少速度快（多信道），6G（WiFi7 新增）频谱宽干扰最小。 详细解释：

频段 信道 特点
2.4G 1/6/11（20MHz 不重叠） 覆盖好、穿墙强，但设备多干扰大（蓝牙/微波）
5G 36-165 多信道（含 DFS） 干扰少、速率高，覆盖稍差
6G WiFi7 新增（5925-7125MHz） 频谱超宽（1.2GHz）、可 320MHz 超大信道、干扰最低
- 信道规划：相邻 AP 用不重叠信道（2.4G 用 1/6/11），同信道 AP 拉开距离——这就是 RRM 信道调优的核心逻辑
- DFS（动态频率选择）：5G 部分信道要避开雷达（检测到雷达自动让出）
话术/例题："2.4G 就 3 个干净信道，5G 一堆，6G 最宽"一句。追问：为什么 2.4G 干扰严重？→ 蓝牙/微波/老旧设备共用 + 只有 3 个不重叠信道。

3. AP/AC 架构：胖 AP vs 瘦 AP、CAPWAP

一句话结论：胖 AP 独立工作（单机配置），瘦 AP 由 AC 集中管理（配置/漫游/认证都靠 AC），云 AP 由云平台管理（你的云简）。 详细解释： - 胖 AP（Fat）：本地有完整功能（转发/认证/管理），适合家庭/小店，运维各自为政 - 瘦 AP（Fit）：只做射频转发，AC 统一管理： - CAPWAP 隧道：AP 与 AC 间控制（配置下发）+ 数据（转发）隧道，UDP 5246/5247 - 好处：集中配置、无缝漫游（AC 协调）、统一认证、集中监控 - 云 AP：AC 功能上云（云简就是），AP 通过公网连云平台，适合连锁/多门店 - 组网：AC+Fit AP（企业传统）、云 AP（SMB/连锁）、本地 AC（园区） 话术/例题："胖=单干、瘦=AC 管、云=平台管"一句。追问：CAPWAP 是什么？→ 无线接入点控制与配置协议，AP 与 AC 之间的控制/数据隧道。

4. WLAN 基本概念：SSID / BSSID / Beacon

一句话结论：SSID 是网络名（可多个），BSSID 是 AP 射频的 MAC 地址，Beacon 是 AP 周期性广播的"自我介绍"。 详细解释： - SSID（服务集标识）：用户看到的 WiFi 名；一个 AP 可广播多个 SSID（多 SSID 隔离） - BSSID：基本服务集标识，即 AP 的 MAC（每射频一个）；手机连接后 AP 角度区分 - ESSID：扩展服务集，多个 AP 同一 SSID 组成漫游域 - Beacon 帧：AP 每 100ms 广播（含 SSID/信道/能力/RSN），手机靠它发现网络 - Probe Request/Response：手机主动探测 - 关联（Association）：手机认证 + 关联后建立连接（四步握手在认证后） 话术/例题："SSID 名字、BSSID 门牌号、Beacon 小广告"比喻。追问：手机怎么发现 WiFi？→ 被动等 Beacon + 主动发 Probe Request。

5. 无线漫游原理（基础）

一句话结论：客户端从 AP1 覆盖移动到 AP2 覆盖，重新认证关联到新 AP（换 BSSID 不换 SSID），期间会短暂断流。 详细解释： - 触发条件：信号变弱（RSSI 低于阈值）/丢包率高/速率低 → 客户端主动扫描找更强 AP - 过程：扫描（主动/被动）→ 认证 → 关联 → （802.1X 场景重认证）→ 新 AP 接入 → IP 不变（同子网二层漫游） - 问题：漫游时延（扫描 50-200ms + 重认证可能 100ms+）→ 语音/视频卡顿 - 粘滞问题（Sticky Client）：客户端"赖着"旧 AP 不走（信号差也不切换）→ AP 侧踢下线/漫游引导 - 二层漫游（同网段，IP 不变）/ 三层漫游（跨网段，要移动 IP/隧道） 话术/例题："信号弱触发 + 重新关联 + IP 不变"三步。追问：漫游时 IP 会变吗？→ 同子网二层漫游不变，跨子网三层漫游要隧道（CAPWAP 数据隧道可以解决）。

6. 快速漫游：802.11r / 802.11k / 802.11v

一句话结论：802.11k 提前告诉你邻居 AP（少扫描），802.11v 引导你切换（解决粘滞），802.11r 快速切换（免完整重认证）——三件套把漫游时延从几百 ms 压到几十 ms。 详细解释： - 802.11k（邻居报告）：AP 告诉客户端"附近有哪些 AP 和信道"→ 客户端不用全信道扫描，直接定位候选 → 省扫描时间 - 802.11v（BSS 过渡管理）：网络侧建议客户端切换到哪个 AP（信号/负载感知）→ 解决粘滞 + 负载均衡 - 802.11r（快速 BSS 切换 FT）：预分配密钥（PMK 缓存），重关联时直接拿密钥跳过完整 802.1X 认证 → 切换 <50ms（VoWiFi 要求） - 组合效果：语音漫游从 200ms+ 降到 <50ms - 你场景：RRM 的漫游引导（调优下发里包含漫游阈值/邻居列表配置） 话术/例题："k 告诉你邻居、v 让你走、r 走快点"口诀，这是通信厂面试的超纲加分。追问：802.11r 怎么做到快？→ 密钥提前分发给目标 AP（PMK-R0/R1 层次化密钥），省掉完整 EAP 认证。

7. 漫游触发与调优参数（RRM 相关）

一句话结论：漫游靠 RSSI 阈值/丢包率触发，参数（最小 RSSI、漫游差量、扫描周期）由 AC/云平台下发——这就是 RRM 调优的内容。 详细解释（你的专业领域，讲出深度）： - 触发参数：最小 RSSI（低于-75dBm 考虑漫游）、漫游差量（新 AP 比当前好多少才切，防乒乓）、丢包率阈值、重试率 - 乒乓效应：两个 AP 边界来回切 → 调大漫游差量/迟滞 - 调优参数怎么下发：AC/云平台 → CAPWAP/Netconf → AP（你做的 WebSocket+netconf 下发就是干这个） - RRM 调优算法输入：AP 采集（信道利用率、邻区 RSSI、客户端分布）→ 云端计算（信道/功率/漫游参数）→ 下发 AP 话术/例题：你能讲"RSSI 阈值 + 漫游差量 + 防乒乓"这些真实参数，普通面试者根本不会。追问：你们调优下发失败怎么处理？→ 重试 + 幂等 + 上报回执（结合你 Kafka 上报链路）。

8. MIMO / MU-MIMO / OFDMA / 波束成形（WiFi5→6/7 核心）

一句话结论：MIMO 多天线并行收发（802.11n 引入），MU-MIMO 同时服务多设备（WiFi5 下行/WiFi6 上下行），OFDMA 把信道切成资源块多用户同时用（WiFi6 标志），波束成形定向增强。 详细解释： - MIMO：多收多发，空间流叠加速率（2×2 = 2 流）；天线越多速率越高（AP 4×4/8×8） - MU-MIMO：多个空间流同时服务不同客户端（WiFi6 支持上下行） - OFDMA：把 20MHz 分成多个 RU（资源单元），多个客户端同时用不同 RU → 低延迟多设备场景质变（对比 OFDM 是轮流独占） - 波束成形（Beamforming）：AP 按客户端位置调整天线相位，信号定向增强（SNR 提升） - WiFi7 升级：MLO（多链路同时收发，手机同时连 2.4+5G）、320MHz、4096-QAM 话术/例题："MIMO 堆速率、OFDMA 分资源、波束定向打"一句。追问：OFDMA 和 OFDM 区别？→ OFDM 一个时刻一个用户用整信道，OFDMA 拆成 RU 多用户同时用。

9. 信道规划与同频干扰（RRM 核心逻辑）

一句话结论：相邻 AP 用不同信道（不重叠）、拉开同信道距离，信道利用率监控是 RRM 自动调信道的前提。 详细解释： - 不重叠信道：2.4G 只有 1/6/11 三个，5G 有几十个（含 DFS） - 干扰类型：同信道干扰（CCA/隐藏节点）、邻信道干扰（5G 较少） - 自动信道规划：AP 扫描周边 → 上报信道占用 → 云/AC 计算最优分配（避免同频重叠）→ 下发；定期重评估（晚上低峰自动调） - 你的 RRM：newApUpScheduler 每 60s 检查新 AP → 空 autoOptDoc 时跳过——就是信道/功率调优任务触发逻辑 话术/例题：讲"AP 扫描 → 云算 → 下发"的闭环 + 你实际调优逻辑，这是 RRM 岗位对口答案。追问：为什么 2.4G 只能 1/6/11？→ 20MHz 信道间隔 25MHz，只有 3 个不重叠。

10. 无线功率与覆盖（RRM 功率调优）

一句话结论：AP 功率决定覆盖半径，功率过大同频干扰、过小有盲区；RRM 根据邻区关系自动调功率达"刚好覆盖"。 详细解释： - 功率与覆盖：增大功率 → 覆盖变大但同频干扰区域也变大（隐藏节点问题加重） - 目标：覆盖连续 + 干扰最小（小区边缘信号合理衔接） - 自动功率调优：AP 上报邻区 RSSI → 云平台算最优功率（目标边缘信号 -75dBm 左右）→ 下发调整 - 你项目：rrmcompute 计算大场所、功率/信道调优是核心功能 话术/例题："功率不是越大越好，覆盖衔接才最优"。追问：功率调太大有什么问题？→ 同频干扰扩大、客户端漫游变差（到处信号都好反而不漫游）。

11. WPA2 / WPA3 安全

一句话结论：WPA2 用 AES-CCMP + 4 次握手，WPA3 解决 WPA2 的弱点（暴力破解/离线攻击），用 SAE 替代 PSK。 详细解释： - WPA2-PSK：预共享密钥 + 4 次握手（生成 PTK）；弱点：离线字典攻击（抓握手包暴力试密码）、KRACK 攻击 - WPA3： - SAE（同时认证）：替代 PSK，防离线字典攻击（每客户端独立密钥派生） - OWE（机会性无线加密）：开放网络也加密（防嗅探） - 802.1X 增强（企业版 192 位安全） - 你场景：云简设备管理平台下发的 WiFi 配置含安全策略 话术/例题："WPA2 握手可被抓包爆破，WPA3 SAE 防离线字典"一句。追问：KRACK 是什么？→ 4 次握手重装攻击，WPA2 设计缺陷，WPA3 修复。

12. 无线接入认证：802.1X / Portal / MAC

一句话结论：802.1X 企业级（证书/账号，最安全）、Portal（网页认证，访客/酒店）、MAC 认证（白名单，简单）；企业办公常用 802.1X。 详细解释： - 802.1X：客户端 → 认证器（AP/交换机）→ RADIUS 服务器（对接 AD/数据库）；EAP-TLS（证书）/PEAP（账号）；漫游时重认证慢 → 靠 802.11r 加速 - Portal：未认证先连开放 SSID → 弹网页输入账号/短信 → 认证后放行（访客 WiFi 标配） - MAC 认证：设备 MAC 白名单，简单但不安全（MAC 可伪造） - 结合漫游：802.1X 漫游重认证开销大 → 802.11r 预分配密钥解决（第 6 题联动） 话术/例题："802.1X 安全、Portal 方便、MAC 简单"选型一句。追问：企业员工 WiFi 用什么？→ 802.1X + RADIUS 对接公司账号。

13. 无线干扰与排查

一句话结论：无线问题 80% 是干扰/覆盖/漫游，排查流程：信道利用率 → 邻区干扰 → RSSI → 重传率 → 空口抓包。 详细解释： - 干扰源：同频 AP、非 WiFi 设备（微波/蓝牙/无线摄像头）、DFS 雷达 - 指标：信道利用率（高=拥堵/干扰）、重传率（>20% 异常）、RSSI/SNR、客户端丢包 - 排查手段：AP 射频扫描报告（你 RRM 的数据源）、wireshark 空口抓包（monitor 模式）、频谱分析仪 - 典型故障：某区域网慢 → 查该 AP 信道利用率 → 发现同信道邻区干扰 → RRM 调信道/降功率 话术/例题："先看信道利用率再看干扰再看重传"的顺序。追问：wireshark 能看 802.11 层吗？→ 网卡切 monitor 模式抓管理帧/数据帧，分析重传/Beacon 丢失。

14. WiFi7（802.11be）新技术深讲

一句话结论：WiFi7 = MLO（多链路同时收发）+ 320MHz（6G）+ 4096-QAM + Multi-RU，你亲手做过 6GHz 全链路适配。 详细解释： - MLO（多链路操作）：设备同时用 2.4+5G 或 5+6G 收发（一个链路丢另一个兜底）→ 延迟大降、可靠性大增——WiFi7 最大卖点 - 320MHz 信道（6G 专属）：速率翻倍 - 4096-QAM：单次传输更多比特（比 WiFi6 的 1024-QAM 高 20%） - Multi-RU：单个用户可用多个 RU（WiFi6 只能一个） - 兼容性：6GHz 设备需要 WiFi7（手机/新笔记本） - 你的 RRM WiFi7 项目：6GHz 频段从 2 频段扩到 3 频段的采集/扫描/计算/调优/下发全链路改造 话术/例题：这是你做过的技术（面试讲项目时直接展开），"MLO 双频并发 + 6G 320MHz"要讲得比面试官深。追问：6GHz 和 2.4/5G 信道规划差异？→ 6G 信道更多更宽，无 DFS 限制（美国之外），干扰最小。

15. RRM 调优算法整体逻辑（终极面试题）

一句话结论：RRM = 自动信道规划 + 自动功率调整 + 漫游负载均衡 + 调优参数下发，目标是最小干扰、最优覆盖、最平滑漫游。 详细解释（把你的工作讲成体系）： 1. 数据采集：AP 周期性上报（信道利用率、邻区 RSSI、客户端分布、干扰源）→ Kafka 到云端 2. 计算：rrmcompute 根据组网规模计算——信道分配（图着色算法思路，邻区尽量异频）、功率（目标边缘信号）、漫游参数（阈值/差量） 3. 下发：rrmcontrol 通过 WebSocket+netconf 下发到 AC/AP（调优参数、生效指令） 4. 上报闭环：设备调优结果 → Kafka → 校验入库（MongoDB 分表）→ 页面展示 5. 架构：AC+fitap 设备侧计算（就近快速）、云 AP 云端计算（集中优化） - 触发方式：新 AP 上线（你的 newApUpScheduler 60s 巡检）、定时（低峰窗口）、手动 话术/例题：这题如果被问到（通信厂必问"你们 RRM 怎么调优"），按"采集→计算→下发→闭环"四步讲，直接展示架构师水平。追问：调优触发后怎么保证不重复？→ Redis 分布式锁 + 任务状态机。

16. 802.1X 与漫游结合 / 无线 QoS

一句话结论：802.1X 漫游重认证开销大用 802.11r 加速；无线 QoS（WMM/802.11e）给语音视频优先队列。 详细解释： - WMM：4 个访问类别（语音/视频/尽力/背景），语音最高优先级 - 语音业务要求：时延 <50ms、丢包 <1% → 需要快速漫游 + WMM + 预留带宽 - 你场景：云 AP 组网里 AC 下发 WMM 配置 话术/例题："WMM 四队列 + 语音优先"。追问：视频会议卡顿排查方向？→ 漫游时延（802.11r 开没开）+ 信道干扰 + WMM 优先级。
