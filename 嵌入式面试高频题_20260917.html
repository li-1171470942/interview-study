1 🔧 C 语言核心（权重最高，必考）

1. 指针和数组的区别？
结论：数组名是地址常量（不能赋值/自增），指针是变量（可移动）。
· sizeof(arr) = 整个数组字节数；sizeof(ptr) = 指针大小（32位4字节/64位8字节）
· 数组名取地址 &arr 类型不同（数组指针），但值相同
· 数组作为函数参数会退化为指针，所以函数内 sizeof 拿不到数组长度
2. ⭐ 函数指针是什么？有什么用？
结论：指向函数的指针，可以把"函数"当参数传递，是实现回调和注册机制的基础。
定义：int (*fp)(int, int); —— 注意括号，否则变成返回指针的函数
用途：① 回调函数（异步通知）② 函数表/注册机制（函数名 → 指针映射）③ 解耦（上层不依赖具体实现）
💡 你的项目：clib 与 Node.js 双向调用就是靠函数指针映射表实现的——C 侧把 JS 注册的函数指针存成全局变量，算完通过 callback 指针回调。这段要能画图讲。
3. 野指针、空指针、悬空指针的区别？
· 空指针：指向 NULL，明确不指向任何对象，可判断
· 野指针：未初始化的指针，指向随机地址 —— 最危险（定义时应初始化为 NULL）
· 悬空指针：指向的内存已被释放（free 后未置 NULL）—— 使用会崩溃
防范：定义时初始化 NULL → 使用前判空 → free 后立即置 NULL
💡 你的项目：终止函数里"回收内存并重置为 null"就是为了防止悬空指针。
4. ⭐ volatile 的作用？能保证原子性吗？
结论：告诉编译器每次都从内存读取，不要优化到寄存器。
场景：① 多线程/多进程共享变量 ② 中断服务函数里被修改的标志位 ③ 硬件寄存器（值可能被硬件改变）
追问"能保证原子性吗？" → 不能！它只保证可见性，不保证原子性（原子性要靠锁或原子操作）
💡 你的项目：压测时用 volatile 全局变量做多进程计数——这是"真的写过 C"的铁证，必须主动讲。
5. const 修饰不同位置的含义？
· const int *p —— 指向的内容不可改（指针可动）
· int * const p —— 指针本身不可改（内容可改）
· const int * const p —— 都不可以改
记忆：const 修饰它右边最近的东西
6. static 的作用？
· 修饰局部变量：生命周期延长到整个程序（存静态区），值保留，但作用域不变
· 修饰全局变量/函数：限制为本文件可见（内部链接），避免命名冲突
· 修饰类成员（C++）：属于类而非对象，所有对象共享
7. 堆和栈的区别？
| | 栈 | 堆 | |--|----|----| | 分配 | 编译器自动 | 程序员手动（malloc/free） | | 速度 | 快 | 慢 | | 大小 | 小（默认 1-8MB） | 大（受物理内存限制） | | 生长方向 | 高→低 | 低→高 | | 碎片 | 无 | 会产生碎片 | 嵌入式坑：栈溢出（递归太深/大数组放栈上）是常见故障
8. malloc/free 的注意事项？内存泄漏怎么产生？
· malloc 后必须判空（可能返回 NULL）
· free 后必须置 NULL（防悬空指针）
· 不能重复 free（double free）
· 泄漏原因：申请后忘记释放 / 异常路径提前 return / 指针被覆盖
· 嵌入式常禁用动态内存（用静态分配避免碎片）
9. 结构体内存对齐规则？
规则：① 每个成员相对结构体首地址的偏移，必须是该成员大小的整数倍 ② 结构体总大小必须是最大成员大小的整数倍
为什么对齐：CPU 访问对齐地址效率高（某些平台不对齐会异常）
优化：把成员按大小从大到小排列可减少填充；#pragma pack(1) 可取消对齐（但影响性能）
10. 如何判断大端还是小端？
大端：高位字节存低地址（网络字节序）；小端：低位字节存低地址（x86/ARM 常见）
判断方法： 
int i = 1;
char *p = (char *)&i;
if (*p == 1) printf("小端");
else printf("大端");
转换：htons/htonl（主机→网络）、ntohs/ntohl（网络→主机）
11. 位操作：如何置位、清位、取反、判断？
· 置位：reg |= (1 << n)
· 清位：reg &= ~(1 << n)
· 取反：reg ^= (1 << n)
· 判断：if (reg & (1 << n))
嵌入式场景：寄存器配置、标志位管理（你项目里的位掩码状态压缩就是这个思路）
12. 宏定义和函数的区别？
· 宏是预处理阶段文本替换，无类型检查、无函数调用开销，但可能重复计算/体积膨胀
· 函数有类型检查、有调用开销
· 宏要加括号防优先级问题：#define MAX(a,b) ((a)>(b)?(a):(b))
· C++ 可用 inline 函数替代宏
13. sizeof 和 strlen 的区别？
· sizeof 是运算符，编译期求值，返回类型/变量占用字节数（含 '\0'）
· strlen 是函数，运行期计算，返回字符串长度（不含 '\0'）
· char s[] = "abc"; → sizeof(s)=4, strlen(s)=3

2 ⚡ 中断与系统

14. ⭐ 中断和轮询的区别？（必考）
中断：事件驱动——外设主动通知 CPU，CPU 暂停当前任务去处理。优点：响应快、不浪费 CPU、省电；缺点：需处理优先级和嵌套
轮询：CPU 主动循环查询状态。优点：实现简单；缺点：占 CPU、实时性差
选择：实时性要求高/低功耗场景用中断；周期性简单任务可用轮询
15. 什么是中断嵌套？优先级怎么处理？
中断嵌套：高优先级中断可以打断正在执行的低优先级中断
优先级反转：低优先级任务持有高优先级任务需要的资源 → 高优先级被阻塞
解决：① 合理配置中断优先级 ② 用互斥锁的优先级继承机制 ③ 临界区尽量短
16. 中断服务函数（ISR）要注意什么？
① 尽量短——耗时操作移到主循环（置标志位，主循环处理）
② 不要阻塞——不能有 sleep/等待
③ 共享变量要加 volatile
④ 注意可重入性（避免使用不可重入函数）
⑤ 中断里不能调用可能引起阻塞的 API
17. 中断和异常的区别？
· 中断：来自外部硬件（异步），如按键、串口接收
· 异常：来自 CPU 内部（同步），如除零、非法指令、缺页
· 两者处理机制类似（都跳转到处理程序），但触发源和时机不同

3 🧵 RTOS

18. 裸机开发和 RTOS 怎么选？
裸机：任务简单、逻辑单一、资源极度受限（用前后台/状态机）
RTOS：多任务协同、需要实时性保证、任务间有同步/通信需求
判断：任务数量多、有优先级差异、需要阻塞等待 → 上 RTOS
19. RTOS 的任务调度机制？
· 抢占式调度：高优先级任务就绪立即抢占 CPU（实时性保证）
· 时间片轮转：同优先级任务轮流执行
· 空闲任务：无任务可跑时执行
关键概念：任务状态（就绪/运行/阻塞/挂起）、上下文切换
20. 什么是优先级反转？怎么解决？
现象：低优先级任务持有互斥锁 → 高优先级任务被阻塞 → 中优先级任务抢占 CPU → 高优先级实际被"中优先级"拖住
解决：① 优先级继承（持锁时临时提升到等待者的优先级）② 优先级天花板 ③ 临界区尽量短
21. 信号量和互斥锁的区别？
· 互斥锁：用于互斥（保护共享资源），有所有权概念，谁加锁谁解锁
· 信号量：用于同步或计数（如生产者-消费者），无所有权，可以在一个任务释放、另一个任务获取
· 二值信号量可当锁用，但没有优先级继承
22. 任务间通信有哪些方式？
① 消息队列（传数据，最常用）② 信号量（同步/互斥）③ 事件标志组（多事件等待）④ 邮箱（传指针）⑤ 全局变量 + 临界区保护
选择：传数据用队列，同步用信号量，多条件等待用事件组

4 🔌 通信总线（嵌入式核心 · 汽车电子重点）

23. UART（串口）的特点？
异步（无时钟线，靠约定波特率）、全双工（TX/RX 两根线）、点对点
关键参数：波特率、数据位、停止位、校验位
典型应用：调试串口、GPS、蓝牙模块
注意：双方波特率必须一致，否则乱码
24. SPI 的特点？
同步（有时钟线 SCK）、全双工、四线（SCK/MOSI/MISO/CS）、速度快（可达几十 MHz）
缺点：每个从设备要一根片选线（CS），设备多了引脚占用大
典型应用：Flash、屏幕、传感器
25. I2C 的特点？
同步、半双工、两线（SCL/SDA）、支持多设备（靠设备地址区分）
优点：引脚少，一条总线挂多个设备
缺点：速度较慢（标准 100kHz，快速 400kHz）
注意：需要上拉电阻；总线仲裁机制
26. ⭐ CAN 总线的特点？（汽车电子核心）
差分信号（CAN_H/CAN_L，抗干扰强）、多主结构（任何节点都可发）、广播式（所有节点都能收到）
核心机制：基于 ID 的仲裁——ID 越小优先级越高，冲突时低优先级自动退让（非破坏性仲裁）
为什么汽车用 CAN：抗干扰强（差分）、可靠性高（CRC 校验 + 自动重发）、线束少（一根总线挂多个 ECU）
速率：经典 CAN 最高 1Mbps；CAN FD 可达 5Mbps+
💡 你是转岗，CAN 没实战经验——诚实说"没做过 CAN，但理解它的差分传输和仲裁机制"，然后类比 TCP/IP 的可靠性设计（你熟），展示可迁移性。
27. 四种总线对比（面试常让列表格）
总线同步/异步双工线数速度多设备
UART异步全双工2（TX/RX）低-中点对点
SPI同步全双工4（+CS）高靠 CS 片选
I2C同步半双工2（SCL/SDA）中靠地址
CAN异步半双工2（差分）中-高多主+仲裁

5 💾 MCU 与硬件基础

28. Flash 和 RAM 的区别？
· Flash：非易失（断电不丢），存程序代码和常量，写入慢、擦写次数有限（约 10 万次）
· RAM：易失（断电丢失），存运行时变量/堆栈，读写快、容量小
延伸：程序运行时代码从 Flash 读（或搬到 RAM 执行，视架构而定）
29. MCU 的启动流程？
① 上电复位 → ② 从固定地址取复位向量 → ③ 执行启动文件（初始化栈指针、堆、中断向量表）→ ④ 初始化时钟/外设 → ⑤ 跳转到 main()
30. 看门狗（Watchdog）的作用？
作用：程序跑飞/死锁时自动复位系统
原理：定时器倒计时，程序必须在超时前"喂狗"（重置计数），否则触发复位
注意：喂狗要放在主循环，不能放在中断里（否则中断正常但主循环卡死就失效了）
31. DMA 是什么？有什么好处？
DMA = 直接内存访问——外设和内存之间传数据不经过 CPU
好处：① 释放 CPU（可并行处理其他任务）② 传输大数据块时效率高
场景：串口大量收发、ADC 采样、屏幕刷新
32. GPIO 的常见模式？
· 输入：浮空 / 上拉 / 下拉 / 模拟
· 输出：推挽（强驱动）/ 开漏（需外部上拉，可线与）
· 复用：作为外设引脚（UART/SPI 等）

6 🐧 Linux 系统编程（你有基础，可加分）

33. 进程和线程的区别？
· 进程：资源分配的基本单位，有独立地址空间，切换开销大
· 线程：CPU 调度的基本单位，共享进程资源，切换开销小
· 通信：进程间要 IPC（管道/共享内存/消息队列/socket）；线程间直接共享变量（需加锁）
34. 进程间通信（IPC）有哪些方式？
① 管道/命名管道 ② 消息队列 ③ 共享内存（最快，需同步）④ 信号量 ⑤ 信号 ⑥ Socket（可跨主机）
你的项目：Node.js 调用 Python 子进程 —— 这就是典型的进程间通信场景，可以举例。
35. 文件 IO 中 open/read/write 与标准 IO（fopen）的区别？
· 系统调用（open/read/write）：直接操作文件描述符，无缓冲，效率低但可控
· 标准 IO（fopen/fread）：有用户态缓冲，减少系统调用次数，效率高
选择：频繁小块读写用标准 IO；需要精确控制（如设备文件）用系统调用
36. 什么是僵尸进程和孤儿进程？
· 僵尸进程：子进程已退出但父进程没回收（未 wait），占用进程表项
· 孤儿进程：父进程先退出，子进程被 init(1) 收养
解决僵尸：父进程调用 wait/waitpid，或忽略 SIGCHLD 信号
